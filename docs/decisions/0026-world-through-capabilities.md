# 0026 세계에 닿는 일은 능력으로만 한다 (os는 열지 않는다)

상태: 사용자 결정 (2026-11-17). 선택지 A.

## 물음

CodeAct는 언어와 VM을 넣어 반복을 줄이고 작업을 배치로 돌리는 방식이다. 그렇다면 `os`, `io` 같은 기능을 막지 말고 스크립트에 다 주는 편이 낫지 않은가.

## 결정

배치의 힘(루프, 조건, 계산, 표준 모듈)은 모두 준다. 세계에 닿는 일(파일, 프로세스, 네트워크, 환경)은 능력으로만 한다. `os`를 스크립트에 열지 않는다. 모델이 아쉬워할 자리는 `os`를 여는 것이 아니라 능력을 넓혀 메운다.

## 근거

- 배치는 이미 된다. 스크립트가 루프 안에서 `fs.read`, `fs.write`, `proc.exec`를 부르면 run 하나로 여러 파일을 다룬다(스파이크 2).
- `os`(`read_file`, `write_file`, `remove_file`, `exec`, `get_env`, `set_env`, `chdir`, `exit` 등)는 능력 층을 거치지 않는다. 05의 2층(정책 게이트, 모드, deny 규칙), 3층(Landlock은 `proc.*`의 자식에 건다), 세션 기록을 비켜 간다. 프롬프트 인젝션이 일으키는 쓰기, 실행, 유출이 05가 막으려는 것이다.
- `exit`, `chdir`, `set_env`는 하네스 프로세스 자신을 바꾼다. `os.exec`는 `proc.exec`의 시간 상한, 표준 입력 차단, 출력 상한, 취소가 없다.

## 확인한 것 (0.4.13, 세션)

- 라이브러리의 기본 로더는 `os`, `libc`, `cli`를 모른다(CLI 전용). 이 결정은 이미 성립해 있고, 호스트가 `os`를 더하지 않는 것으로 지킨다.
- 기본 로더가 주는 것은 core, meta, c, math, cy, io, test와 표준 모듈 json, toon, regex, peg, time이다. `io`는 str을 읽는 Reader, Scanner라 세계에 닿지 않는다.
- 로더는 스크립트의 `use`와 모듈 안의 `use`를 구별하지 못한다. 그래서 허용 목록에 의존 모듈 `meta`(core, json, math가 쓴다)와 `c`(math가 쓴다)를 넣는다. 허용 목록: core, meta, c, math, json, toon, regex, peg, time, path, 그리고 호스트 능력 모듈. `io`, `cy`, `test`는 싣지 않는다(가르치지 않고 필요가 없다. 위험해서가 아니다).
- `c`는 deny_raw_ptrs 아래에서 포인터 함수(`to_strz`, `from_strz`, `memcpy`)가 컴파일 오류이고, -Dffi=false라 extern 호출이 panic 결과다. 이전 로더는 `c`를 막아서 `use math`가 실패하고 있었다.
- `c`가 실려 있지 않을 때 `#[extern]` 함수가 있는 스크립트는 0.4.13에서 검증 중에 프로세스를 죽였다. cyber 0.4.14에서 선언 위치의 컴파일 오류가 됐다(s1 검사 7h).
- cyber 0.4.14부터 호스트 resolver가 소스의 use만 받는다(컴파일러 내부 조회는 resolver를 부르지 않는다). `curUri`가 `main`인 use만 허용 표와 맞추면 스크립트의 `use c`, `use meta`를 막으면서 `use math`가 된다. cyber는 `cy.eval`(새 VM이 호스트 설정을 물려받지 않는다)과 `meta.load`(컴파일 시점에 파일을 읽는다)를 스크립트에서 막을 근거로 든다. 지금 허용 목록에는 `cy`가 없다. resolver를 더할지는 본체의 runtime 단계에서 정한다. 그때 extern 문구(``Add `use c`.``)와 다투지 않게 resolver의 거부 문구를 정한다. 0.4.14의 기본 거부 문구는 ``Failed to resolve module `c`.``처럼 모듈 이름을 말한다.

## 적용

- 05 1층, 03, 01, 08을 허용 목록으로 고쳤다. spike/s1, s2의 로더를 허용 목록으로 바꿨다(s1 검사 7a, 7a2). path는 ADR 0027(검사 7a3).
- 능력을 넓힐 후보(04 "os 대신 능력으로"): 디렉터리 만들기, 지우기, 옮기기와 복사, 환경 변수 읽기, 작업 디렉터리. 지금은 `proc.exec`로 된다. 따로 능력으로 만들지는 본체의 caps 단계에서 평가를 보고 정한다.
- 모델은 cyber 가이드에서 `os.read_file`을 배운다. 안내의 호스트 덧붙임이 "`os` 대신 `fs.*`, `proc.*`"를 말한다(ADR 0022).

## 방향 (D)

cyber에 임베딩 옵션을 요청해 `os`의 함수를 호스트 콜백으로 받는다. 모델은 익숙한 `os.*`를 쓰고, 호출은 tars-agent의 게이트와 샌드박스를 지난다. `exit`, `chdir`, `malloc`처럼 호스트가 받아서는 안 되는 함수를 나눠야 한다. 지금 하지 않는다. TODO C3과 같은 줄기다.

## 버린 대안

- `os`를 bypass 모드에서만 연다: `exit`, `chdir`, 멈춤은 bypass에서도 문제다. 모드가 주입 집합을 바꾸지 않는다는 05의 캐시 규칙과 부딪힌다.
- `os`를 다 연다: 2층, 3층, 기록, 멈춤 방지를 잃는다.
