# 0024 time 모듈을 허용하고 능력 clock.now를 뺀다

상태: 사용자 결정 (2026-11-17). 선택지 A.

## 결정

표준 모듈 `time`을 스크립트에 연다. 시계 읽기 능력 clock.now는 두지 않는다. 지금 시각은 `time.now()`(벽시계), 경과 시간은 `time.monotonic()`, 시간대는 `time.zone(name)`과 `time.local()`로 얻는다.

## 근거

- cyber 0.4.13의 `time`은 계산만 하는 모듈이 아니다. 호스트 함수 다섯(`real_ns_`, `mono_ns_`, `tz_read_`, `tz_local_`, `tz_local_data_`)으로 시계 둘, `$TZ`·`$TZDIR`, `/etc/localtime`, zoneinfo 파일을 직접 읽는다. "시계 읽기는 능력, 계산은 time"이라는 명세의 나눔은 성립하지 않는다.
- time을 막으면 날짜 계산, 시간대 변환, 포맷 수단이 없다. time을 열면 clock.now가 따로 주는 것은 시각 읽기가 세션 기록에 남는다는 것 하나다.
- 위험은 작다. 읽는 것은 시각, 로컬 시간대, `$TZ` 값이다. zoneinfo 읽기는 이름 꼴(`Area/Location`) 검사, 크기 상한, TZif 헤더 확인을 거친다.
- 모델은 cyber의 agent-guide.md(ADR 0022)에서 `time`을 배운다. 호스트만의 시계 능력을 따로 가르치지 않아도 된다.

## 치르는 것

- 시각 읽기가 능력 층을 거치지 않아 세션 기록(07)에 남지 않는다. 리플레이에서 `time.now()`는 다른 값을 낸다. 날짜가 출력에 들어간 run은 리플레이 대조가 어긋날 수 있다.
- 능력 통계에 시각 읽기가 잡히지 않는다.

## 다시 볼 때

리플레이의 결정성이 필요해지면(본체의 07 단계) 아래 순서로 본다.

- B. 호스트 로더가 time의 시계 함수(`real_ns_`, `mono_ns_`)를 tars-agent 것으로 바꿔 끼워 기록을 남긴다. 기본 로더가 붙인 내장 모듈의 함수를 덮어쓸 수 있는지는 확인하지 않았다.
- C. cyber에 임베딩 옵션으로 time의 시계와 시간대 원천을 호스트 콜백으로 받게 요청한다(TODO C3과 같은 줄기).

## 버린 대안

- time을 막고 clock.now만 둔다: 날짜 계산을 모델이 손으로 해야 한다.
- 둘 다 둔다: 같은 일을 두 길로 하게 되고, 모델은 가이드에서 배운 `time.now()`를 쓴다.
