# 0017 M0 스파이크의 발견과 본체에 대한 추천

상태: 발견은 확정 (cyber master 63e35e88, 2026-11-14, 실측). 추천은 확정이 아니다. 본체를 만들 때 단계마다 사용자가 정한다 (ADR 0012의 덧붙임).

상세: docs/spikes/2026-11-14-m0-spikes-review.md. cyber 요청: docs/requests/cyber-m0-spike-requests.md.

## 증명된 것

- Zig 0.17.1 호스트가 libcyber를 정적 링크해 VM을 돌린다. 호스트 경계 검사 35개 중 34개가 macOS arm64에서 통과했다(남은 하나는 아래의 열린 결함). x86_64-linux-gnu 교차 빌드도 된다.
- 능력은 `Future[!str]`을 돌려주고 str 값이나 오류로 완료한다. 머리말 래퍼가 await하고 모델은 `fs.read(path) -> !str`만 본다.
- 승인 대기를 VM 밖에서 하는 설계(0011, 0016)가 고칠 것 없이 돈다: 승인, 거부, 취소, 버린 요청, 동시 요청, 중첩 scope.
- 검증을 세션 VM에서 바로 할 수 있다. 보통의 컴파일 실패 뒤에도 세션이 그대로다.
- 상한 넷이 폭주를 멈추고 VM은 계속 쓸 수 있다. spawn 스레드 안의 폭주도 연료가 멈춘다.
- Zig std.http로 스트리밍 요청이 된다. curl 대안은 필요 없다.
- 0015의 방향이 맞다. 블록 넷과 thinking의 불투명 칸 하나로 두 형식, 제공자 둘, 모델 셋을 받았다.
- 기준 빌드에 맞춘 안내로 CodeAct가 과제 셋을 모델 셋으로 21번 모두 끝냈다(direct도 6번 모두). 컴파일 오류는 작은 모델(qwen3.8-flash)에 과제당 1.3번이었고 모두 다음 스텝에 고쳐졌다.

## cyber에 남은 것

- 문자열 이스케이프 오류(`"a\|b"`, `'\xZZ'`)가 세션의 변수, 함수, use를 알림 없이 지운다. 모델이 회차에서 실제로 겪었다.
- `\0`이 큰따옴표가 된다.
- 의존으로 받아도 라이브러리 아티팩트가 나오지 않는다. 의존으로 빌드한 라이브러리의 버전 문자열에 커밋이 없다.
- spawn을 막는 옵션이 없고 스레드 안에서 능력 함수가 불린다.
- 호스트 함수의 인자 읽기 순서가 문서에 없고, 어기면 죽는다.
- 모델이 따라가는 오류 문구 넷(세션에서 안 되는 최상위 빌림 제안, `_len` 제안, `not`을 `?T`에 쓴 오류의 `!`, Rust식 메서드 이름에 제안 없음).

## 스파이크 안에서 Claude가 정한 것 (위임받은 결정)

- 순서: 스파이크 1, 2a, 2b, 3. 위험이 큰 호스트 경계부터 했다.
- cyber.h는 translate-c 패키지로 가져왔다. 본체의 추천은 손으로 쓴 extern이다.
- 라이브러리는 받은 패키지에서 `zig build lib`를 돌려 얻었다. 본체에는 넣지 않는다.
- 모델이 쓴 명령은 샌드박스에서만 돌렸다(macOS sandbox-exec: 쓰기는 작업 폴더, 네트워크 차단, 사용자 폴더 읽기 차단, 명령당 20초).
- 안내 문서(prompt/cyber-subset*.md)를 기준 빌드로 다시 썼다. 항목은 탐침으로, 코드 블록은 CLI와 세션 양쪽에서 확인했고, CodeAct 회차에서 모델이 틀린 곳(`?int` 다루기, 이스케이프, 블록 안의 `fn`)을 더했다. 문구가 고치는 법을 말하는 오류는 안내에서 뺐다.
- 스파이크 코드는 spike/에 커밋해 두었다. 검토가 끝나면 지운다.

## 본체에 대한 추천

검토 문서 9절의 열여섯 항목이다. 구조에 닿는 것만 여기 옮긴다.

1. 명세 01의 구성요소와 경계는 그대로 간다.
2. 능력은 모두 `Future[!T]`를 돌려주고 머리말 래퍼가 await한다. 승인이 필요 없으면 호스트 함수 안에서 바로 완료한다.
3. 검증은 세션 VM에서 바로 한다. 호스트는 세션이 reset된 것을 알고 모델에게 알린다(cyber의 알림 길이 선행 조건).
4. 호스트 로더는 허용 목록이다. 능력 함수는 메인 스레드가 아니면 panic을 돌려준다.
5. 프로세스 실행 능력은 자체 시간 상한, 표준 입력 차단, 출력 상한, 취소를 가진다. VM의 타이머는 승인 뒤 루프가 돌리는 프로세스에 닿지 않는다.
6. 읽기 능력도 권한의 대상이다. 읽은 것은 모두 모델 제공자에게 간다.
7. (2026-11-13 사용자 지시) 결함은 모두 고치고 진행한다. 요청서 1~5절이 닫힌 것이 본체 첫 단계의 선행 조건이다 (ADR 0019).
8. 안내 문서의 예제와 조언은 세션 VM에서 확인한다. 안내는 회차에서 모델이 틀린 곳으로 고치고, 문구가 고치는 법을 말하는 오류는 넣지 않는다.
9. direct 모드는 대조군이면서 작은 모델용 기본값 후보다.
