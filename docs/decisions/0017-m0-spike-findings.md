# 0017 M0 스파이크의 발견과 본체에 대한 추천

상태: 발견은 확정 (cyber 로컬 master 6a155275, 2026-11-14, 실측). 추천은 확정이 아니다. 본체를 만들 때 단계마다 사용자가 정한다 (ADR 0012의 덧붙임).

상세: docs/spikes/2026-11-14-m0-spikes-review.md. cyber 요청: docs/requests/cyber-m0-spike-requests.md.

## 증명된 것

- Zig 0.17.1 호스트가 libcyber를 build.zig.zon 의존의 아티팩트로 정적 링크해 VM을 돌린다. 호스트 경계 검사 40개가 macOS arm64에서 모두 통과했다. x86_64-linux-gnu 교차 빌드도 된다.
- 능력은 `Future[!str]`을 돌려주고 str 값이나 오류로 완료한다. 머리말 래퍼가 await하고 모델은 `fs.read(path) -> !str`만 본다.
- 승인 대기를 VM 밖에서 하는 설계(0011, 0016)가 고칠 것 없이 돈다: 승인, 거부, 취소, 버린 요청, 동시 요청, 중첩 scope.
- 검증을 세션 VM에서 바로 할 수 있다. 컴파일 실패 뒤에도 세션이 그대로다. 세션이 reset되는 경우(VM의 첫 컴파일 실패, 할당 실패)는 cl_vm_reset_pending으로 안다. panic과 interrupt 뒤에는 최상위 변수만 사라진다.
- 상한 넷이 폭주를 멈추고 VM은 계속 쓸 수 있다. deny_spawn으로 spawn을 막으면 능력은 eval 스레드에서만 불린다.
- Zig std.http로 스트리밍 요청이 된다. curl 대안은 필요 없다.
- 0015의 방향이 맞다. 블록 넷과 thinking의 불투명 칸 하나로 두 형식, 제공자 둘, 모델 셋을 받았다.
- 기준 빌드에 맞춘 안내로 CodeAct가 과제 셋을 모델 셋(DeepSeek은 사고 없음과 기본 effort high 두 모드)으로 36번 모두 끝냈다(direct도 6번 모두). 컴파일 오류는 작은 모델(qwen3.8-flash)에 과제당 2.1번(앞 빌드 2.4)이었고 모두 그 과제 안에서 고쳐졌다. 그 절반 남짓이 `!str`을 풀지 않고 출력한 것이다. 세션 reset, panic, 상한은 없었다.

## cyber에 남은 것

- 기준 커밋이 원격에 없다. 스파이크는 로컬 경로 의존으로 받는다.
- 회차에서 문구가 고치는 법을 말하지 않은 다섯(`# 주석`, `for f |{...}|:`, 튜플 반환 타입, 홑따옴표 안의 줄바꿈, 슬라이스 경계의 `?int`). 선행 조건은 아니다.

## 스파이크 안에서 Claude가 정한 것 (위임받은 결정)

- 순서: 스파이크 1, 2a, 2b, 3. 위험이 큰 호스트 경계부터 했다.
- cyber.h는 translate-c 패키지로 가져왔다. 본체의 추천은 손으로 쓴 extern이다.
- 기준 커밋이 원격에 없어 cyber를 로컬 경로 의존으로 받았다. 본체에는 넣지 않는다.
- 모델이 쓴 명령은 샌드박스에서만 돌렸다(macOS sandbox-exec: 쓰기는 작업 폴더, 네트워크 차단, 사용자 폴더 읽기 차단, 명령당 20초).
- 안내 문서(prompt/cyber-subset*.md)를 기준 빌드로 다시 썼다. 항목은 탐침으로, 코드 블록은 CLI와 세션 양쪽에서 확인했고, CodeAct 회차에서 모델이 틀린 곳(`?int` 다루기, 이스케이프, 블록 안의 `fn`)을 더했다. 문구가 고치는 법을 말하는 오류는 안내에서 뺐다. `and`로 묶은 옵션 풀기와 보간 안의 보간은 기준 빌드의 문구가 고치는 법을 말하므로 안내에 넣지 않았다.
- 스파이크의 능력은 반환 슬롯을 먼저 받는다. s2는 deny_spawn을 켜고, 실패한 검증과 eval 뒤 cl_vm_reset_pending이 true면 머리말을 다시 돌려 모델에게 알린다.
- 스파이크 코드는 spike/에 커밋해 두었다. 검토가 끝나면 지운다.

## 본체에 대한 추천

검토 문서 9절의 열여섯 항목이다. 구조에 닿는 것만 여기 옮긴다.

1. 명세 01의 구성요소와 경계는 그대로 간다.
2. 능력은 모두 `Future[!T]`를 돌려주고 머리말 래퍼가 await한다. 승인이 필요 없으면 호스트 함수 안에서 바로 완료한다.
3. 검증은 세션 VM에서 바로 한다. 호스트는 CL_SUCCESS가 아닌 eval과 검증 뒤 cl_vm_reset_pending을 묻고, reset이면 머리말을 다시 돌려 모델에게 알린다. panic과 interrupt 뒤에는 최상위 변수가 사라졌다고 알린다.
4. 호스트 로더는 허용 목록이다. deny_raw_ptrs와 deny_spawn을 켠다.
5. 프로세스 실행 능력은 자체 시간 상한, 표준 입력 차단, 출력 상한, 취소를 가진다. VM의 타이머는 승인 뒤 루프가 돌리는 프로세스에 닿지 않는다.
6. 읽기 능력도 권한의 대상이다. 읽은 것은 모두 모델 제공자에게 간다.
7. (2026-11-13 사용자 지시) 결함은 모두 고치고 진행한다. 기준 커밋이 원격에 올라 URL과 해시로 고정되는 것이 본체 첫 단계의 선행 조건이다 (ADR 0019).
8. 안내 문서의 예제와 조언은 세션 VM에서 확인한다. 안내는 회차에서 모델이 틀린 곳으로 고치고, 문구가 고치는 법을 말하는 오류는 넣지 않는다.
9. direct 모드는 대조군이면서 작은 모델용 기본값 후보다.
