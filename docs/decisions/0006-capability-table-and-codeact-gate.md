# 0006 능력 표 단일 소스와 CodeAct 판정 기준

상태: 확정 (2026-11-10). 판정 자체는 M0 평가 뒤에 기록한다.

## 결정 1: 능력 표

능력은 Zig comptime 표 하나에 정의하고, 본체는 VM을 모른다. 표에서 Cyber 선언과 바인딩, 프롬프트 사양, JSON Schema, 등급 표를 생성한다.

근거

- Cyber 값의 소유권 해제를 빠뜨리면 호출마다 샌다 (cyber 쪽 기록에 실제 사례가 여럿이다). 해제를 생성된 바인딩 한 곳에 두면 본체 작성자가 틀릴 수 없다. 권한 게이트 호출도 같은 자리에 둔다.
- 사양 문서와 실제 시그니처가 어긋날 수 없다.
- JSON Schema가 같이 나오므로 direct 모드와 MCP 서버 방향이 추가 설계 없이 가능하다.

## 결정 2: direct 모드

같은 능력 표를 API 도구 여럿으로 노출하고 VM을 쓰지 않는 모드를 M0부터 둔다. 이전 계획의 "JSON 도구 폴백(P6 후속)"을 앞으로 당긴 것이다.

근거: 이 프로젝트에서 가장 불확실한 것은 모델이 Cyber를 얼마나 정확히 쓰느냐다. 대조군 없이는 CodeAct의 이득과 손해를 말할 수 없다.

## 결정 3: 판정 기준

과제 20개 × 3회, 기본 모델(claude-opus-5-5)에서

- 첫 시도 validate 통과율 70% 이상
- 과제 성공률이 direct 모드보다 5%p 넘게 낮지 않음

둘 다 넘으면 CodeAct가 기본이다. 못 미치면 안내 문서를 실패 유형에 맞춰 고치고 한 번 더 잰다. 그래도 못 미치면 direct를 기본으로 하고 CodeAct는 선택 모드로 남긴다. 어느 쪽이든 능력, 권한, 세션, 프런트엔드는 그대로 쓴다.

수치는 시작점이다. 평가를 돌려 본 뒤 바꾸면 이 문서에 이유를 적는다.
