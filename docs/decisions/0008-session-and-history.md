# 0008 세션 기록, 재개, 컴팩션

상태: 확정 (2026-11-10). 상세는 spec/02, 07.

## 결정

1. 세션 기록, 감사 로그, 리플레이 재료는 JSONL 파일 하나다.
2. 히스토리는 덧붙이기만 한다. 보낸 메시지를 고치거나 지우지 않는다. 세션 중 바뀌는 지시는 system 역할 메시지를 덧붙인다.
3. 컴팩션은 요약으로 새 히스토리를 시작하는 방식이다.
4. 재개할 때 VM 상태를 복원하지 않는다. 히스토리, memo, 할 일 목록, 파일 상태만 복원하고 모델에 VM이 새로 시작됐음을 알린다.

## 근거

- 2: 현재 Claude 모델은 사고 블록을 그것을 만든 대화에 묶는다. 앞부분을 고치면 사고 블록이 무효가 되고 프롬프트 캐시도 깨진다. 덧붙이기만 하는 하네스는 두 문제를 처음부터 피한다.
- 3: 히스토리 중간의 오래된 결과를 요약으로 바꿔치기하는 이전 안은 2와 충돌한다. 새 히스토리로 시작하면 규칙이 단순하다.
- 4: 이전 TODO의 "히스토리 코드를 재생해 VM 복원"은 fs.write, proc.exec 같은 부작용을 다시 일으킨다. 부작용 없는 코드만 골라 재생하는 것은 판정이 어렵고 틀리면 위험하다. panic과 인터럽트에서도 변수는 사라지므로 모델은 이미 "변수는 믿을 수 없고 남길 것은 memo에 둔다"는 규칙 아래에 있다. 재개를 같은 규칙으로 다루면 새 개념이 없다.

## 결과

- memo 능력이 필수가 된다.
- 세션 파일 형식에 버전을 둔다.
