# 스파이크에서 발견한 결함은 모두 고치고 진행한다

상태: 사용자 지시 (2026-11-13). "스파이크에서 발견하는 결함은 모두 고치고 진행한다. 기억해둬."

## 규칙

스파이크가 드러낸 결함은 우회한 채로 본체에 들어가지 않는다. 결함을 모두 고친 뒤에 다음 단계로 간다.

## 적용

- 결함이 이웃 저장소(cyber, tars-linux)의 것이면 재현과 함께 요청서를 쓰고, 수정이 릴리스돼 고정 버전을 올리고 재현이 통과하는 것을 확인한 뒤에 진행한다. 이웃 저장소를 직접 편집하는 것은 사용자가 지시할 때다 (ADR 0013).
- 스파이크의 우회(임시 대응)는 본체에 옮기지 않는다. 우회는 스파이크를 끝까지 돌려 나머지를 보기 위한 수단이다.
- 수정이 들어오면 스파이크의 재현을 다시 돌려 확인하고, 우회를 걷어 낸 모양으로도 통과하는지 본다.
- 결함 목록은 요청서와 TODO의 cyber 작업 줄기에 두고, 닫힐 때마다 표시한다.
- 앞으로의 스파이크에도 같은 규칙이다.

## M0 스파이크에 적용하면 (ADR 0017)

본체 첫 단계 전에 닫을 것:

1. 실패한 컴파일 뒤 다음 컴파일에서 죽는 것. 우회(검증을 fork한 자식에서)는 본체에 넣지 않는다.
2. `!str` 값 복사의 컴파일 오류. 우회(손잡이와 take)는 본체에 넣지 않는다. 능력은 `Future[!str]`을 그대로 돌려준다.
3. 빌드 내보내기. 우회(build.zig에서 `zig build lib` 실행)는 본체에 넣지 않는다.
4. spawn 차단 옵션. 스레드 안에서 능력 함수가 불린다.
5. 호스트 함수의 인자 읽기 순서를 어기면 죽는 것 (문서 또는 확인).

결함이 아니라 설계 과제인 것(프로세스 실행의 시간 상한, 읽기 권한, 허용 목록 로더, 안내 문서의 메서드 표)은 본체의 해당 단계에서 만든다.
