# 0007 권한 모델

상태: 확정 (2026-11-10). 상세는 spec/05.

## 결정

1. 프로파일과 모드를 나눈다. 프로파일은 세션 시작 때 정해지는 능력 집합이고, 없는 능력은 주입되지 않는다. 모드는 세션 중에 바뀌며 게이트의 판정만 바꾼다.
2. 프로세스 실행 능력을 둘로 나눈다. proc.exec(인자 배열, 셸 없음)와 proc.sh(셸 문자열). 셸 문자열을 파싱해 안전을 판정하는 분류기는 만들지 않는다.
3. 실행된 프로세스는 Landlock으로 가둔다. 자동 허용(auto 모드)은 샌드박스가 있을 때만 가능하다.
4. 규칙은 Claude Code와 같은 꼴(능력(패턴), allow/ask/deny)이고 설정 파일은 사용자, 프로젝트, 개인 세 층이다. 형식은 JSON이다.
5. 프롬프트 인젝션 대응은 세션 단위 외부 입력 표시다. 표시가 서면 자동 허용이 ask로 내려간다.

## 근거

- 1: 초기 요구사항의 "허용되지 않은 능력은 이름이 주입되지 않는다"는 강한 보장이지만, 모드를 바꿀 때마다 주입 집합이 바뀌면 시스템 프롬프트가 바뀌어 프롬프트 캐시가 깨지고 VM의 모듈도 다시 올려야 한다. 강한 보장은 프로파일에, 자주 바뀌는 것은 게이트에 두면 둘 다 얻는다.
- 2: 셸 문법은 치환, 인용, 별칭, 환경 변수로 뜻이 바뀐다. 문자열을 보고 "읽기 전용"이라 판정하는 장치는 우회 사례가 계속 나오는 것으로 알려져 있다. 인자 배열은 보이는 것이 실행되는 것이라 규칙 맞춤이 정확하다. CodeAct에서는 출력 가공을 스크립트가 하므로 파이프가 덜 필요하다.
- 3: 승인 피로를 줄이는 믿을 만한 방법은 범위 밖을 건드릴 수 없게 만든 뒤 묻지 않는 것이다. Landlock은 의존과 root가 필요 없고 tars 커널(6.18)이 지원한다. seccomp는 tars 커널에 없다.
- 4: Zig 표준 라이브러리에 JSON 해석기가 있어 의존이 없다. 본보기와 같은 꼴이라 설명이 쉽다.
- 5: 값 단위 오염 추적은 CodeAct에서 스크립트 안의 흐름까지 따라가야 해 만들기 어렵다. 세션 단위는 거칠지만 구현이 한 줄이고 놓치는 경우가 없다.

## 남는 약점

- macOS 개발 호스트에는 샌드박스가 없다. auto 모드는 accept-edits로 내려간다.
- Landlock은 읽기를 막지 않게 구성한다. 읽기 보호는 deny 규칙과 네트워크 차단에 기댄다.
