# 0019 스파이크에서 발견한 결함은 모두 고치고 진행한다

상태: 사용자 지시 (2026-11-13). "스파이크에서 발견하는 결함은 모두 고치고 진행한다. 기억해둬."

## 결정

스파이크가 드러낸 결함은 우회한 채로 본체에 들어가지 않는다. 결함을 모두 고친 뒤에 다음 단계로 간다.

## 적용

- 결함이 이웃 저장소(cyber, tars-linux)의 것이면 재현과 함께 요청서를 쓰고, 수정이 들어오면 고정 버전을 올리고 재현이 통과하는 것을 확인한 뒤에 진행한다. 이웃 저장소를 직접 편집하는 것은 사용자가 지시할 때다 (ADR 0013).
- 스파이크의 우회(임시 대응)는 본체에 옮기지 않는다. 우회는 스파이크를 끝까지 돌려 나머지를 보기 위한 수단이다.
- 수정이 들어오면 스파이크를 우회 없는 본래 모양으로 고쳐 다시 돌린다. 재현 코드는 지우고, 지금 동작을 확인하는 보통 검사로 남긴다.
- 문서는 지금의 상태만 적는다. 고쳐진 결함과 걷어 낸 우회의 이야기는 문서에 남기지 않는다(git 이력에 있다). 옛 기록이 다음 작업의 판단을 흐리지 않게 하려는 것이다 (2026-11-14 사용자 지시, ADR 0020).
- 열린 결함 목록은 요청서와 TODO의 cyber 작업 줄기에 둔다.
- 앞으로의 스파이크에도 같은 규칙이다.

## M0 스파이크에 적용하면 (ADR 0017)

본체 첫 단계 전에 닫을 것 (요청서 docs/requests/cyber-m0-spike-requests.md의 1~5절):

1. 문자열 이스케이프 오류가 세션을 알림 없이 지우는 것 (s1 검사 6i). 안내의 이스케이프 줄은 피하는 법이지 수정이 아니다.
2. `\0`이 큰따옴표가 되는 것.
3. 빌드 내보내기. build.zig에서 `zig build lib`를 실행하는 우회는 본체에 넣지 않는다.
4. spawn 차단 옵션. 스레드 안에서 능력 함수가 불린다.
5. 호스트 함수의 인자 읽기 순서의 문서. 순서를 어기면 죽는다.

결함이 아니라 설계 과제인 것(프로세스 실행의 시간 상한, 읽기 권한, 허용 목록 로더, 안내 문서의 메서드 표)은 본체의 해당 단계에서 만든다.
