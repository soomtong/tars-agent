# 0030 fx에서 가져온 것

상태: 확정 (2026-11-20, 사용자가 추천안을 받음). 검토 대상은 vercel-labs/fx `5960bc93d`. 검토 문서는 references/2026-11-20-fx-agent-review.md, 상세는 spec/06, 07, deps.md.

fx는 Zig 0.17.1로 쓴 코딩 에이전트다. 도구는 JSON 도구 호출이고 auto 모드는 모델 검토자에 기댄다. 루프, 세션, 프로토콜, 시험 방법을 우리와 맞대어 보았다.

## 결정

지금 받는 것

1. 세션 파일의 줄 머리: 줄마다 `v`, `seq`, `ts`, `type`을 이 순서로 쓰고 끝에 `crc`(CRC32C)를 붙인다. 줄 하나는 4 MiB까지. 더 새 `v`의 세션은 재개하지 않는다 (검토 A2).
2. 세션 파일의 내구성: 줄 하나를 write 한 번으로 덧붙인다. fsync는 턴을 닫는 줄 뒤에만 한다. 재개할 때 찢긴 꼬리는 잘라 내고, 중간의 깨진 줄은 손상으로 보고 재개를 거부한다. 새 세션은 임시 이름으로 만든 뒤 rename한다 (검토 A3).
3. 세션 하나에 쓰는 프로세스는 하나: `<세션 ID>/lock`에 flock을 쥔다. 잡지 못하면 2초 다시 시도한 뒤 재개를 거부하고 쥔 pid를 말한다. 읽기 도구는 잠그지 않는다 (검토 A4).
4. 헤드리스 json 결과의 모양을 정한다: 결과, 멈춘 이유, 스텝, run마다 검증과 결과 종류와 능력 호출, 사용량, 비용. 필드는 더하기만 한다. 평가(eval/)가 이 출력을 읽는다 (검토 A12).
5. Zig 0.17.1에서 피할 것을 deps.md에 적는다: HTTP 요청 정리가 열린 스트림에서 멈춤, Linux libc의 tcgetattr 스택 넘침, macOS의 Select 취소 뒤 connect panic, allocator 훑기의 흔들림 (검토 B1).

정할 때 함께 보는 것

6. 코어-프런트엔드 이벤트 타입을 편집할 때: 도구 카드의 임시와 확정 구분, 결과 종류(denied, cancelled 포함), 턴 끝에 열린 카드 닫기, 승인 요청의 출처, ACP와 맞춘 멈춘 이유 (검토 A9, ADR 0029).
7. 능력 표를 편집할 때: 행마다 reads_only, irreversible 술어를 두고 권한 문이 컴파일 때 모양을 검사할지 (검토 A10).
8. 그 단계에서 다시 보는 것: 복구를 순수 모듈로(A11, M1 provider), steering 경계(A8, M3), 컴팩션의 원문 유지와 접은 기록 다시 열기(A6, A7, M4), 크래시 뒤 스스로 이어 가기(A5), terminalSafe와 경계 검사 스크립트(B3, B4, M1), 디코더별 fuzz, 크기와 시작 시간 예산, TLA+ 모델(B5~B7).

## 근거

- 1: 잘린 줄은 대개 JSON으로 읽히지 않지만, 잘린 앞부분이 우연히 온전한 JSON이 되는 경우와 디스크 손상은 파서로 가를 수 없다. CRC가 가른다. 머리 순서를 고정하면 stats와 리플레이가 type만 보고 줄을 고를 수 있다.
- 2: kill -9와 크래시에는 write가 끝난 줄이 남는다(OS가 갖고 있다). fsync가 지키는 것은 기계가 멈추는 경우뿐이다. 스텝마다 줄이 여럿이라 매번 fsync하면 비싸고, 잃어도 끊긴 턴 하나다. run 줄을 실행 전에 쓰는 규칙(02)은 프로세스 크래시에 대해 그대로 성립한다.
- 3: 같은 세션을 두 프로세스가 이어 쓰면 seq가 섞이고 히스토리가 갈라진다. 패널마다 tars-agent를 띄우는 모델(ADR 0004)에서 같은 세션을 두 번 여는 일은 실제로 생긴다. flock은 프로세스가 죽으면 커널이 풀어 묵은 잠금이 남지 않는다.
- 4: 평가의 기록 항목(첫 시도 validate 통과율, 스텝 수, 토큰, 실패 종류, TODO M0)을 출력 하나에서 읽게 한다. fx의 평가도 `fx ask --json` 위에 있다.
- 5: 첫째는 provider 스트리밍의 취소에, 둘째는 tars-linux의 줄 편집기에 바로 걸린다. 컴파일 오류 없이 지나가는 것들이라 쓰기 전에 알아야 한다.

## 가져오지 않는 것

- 코어와 프런트엔드를 콜백 구조체로 잇기: 묻는 것과 밀어 주는 것이 섞인다. 01대로 이벤트 하나의 tagged union과 명령 타입을 둔다.
- auto 모드의 근거를 모델 검토자에: 우리 auto는 샌드박스와 능력 표에 기댄다(ADR 0007). 검토자의 설계는 검토 문서 1절에 남긴다.
- 셸 명령 분류기: ADR 0007에서 버렸다.
- 로그인 셸 환경을 떠서 재생하기: v1 밖.
- 전송 오류의 무한 재시도: 헤드리스와 평가에는 끝이 있어야 한다. 상한을 둔다(02).
- 전역 Io 접근자(`getIo()`): `io`를 인자로 넘긴다.
- 코드 크기용 공유 JSON 파서와 정렬: 크기가 문제가 될 때 다시 본다.
- fx의 파일을 베끼기: fx는 Apache-2.0이다. 모두 재구현한다(ADR 0003).
