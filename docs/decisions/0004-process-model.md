# 0004 프로세스 모델

상태: 확정 (2026-11-10). 0002의 "데몬" 부분을 바꾼다. Zig + libcyber는 그대로다.

## 결정

v1은 세션 하나에 프로세스 하나다. 실행 파일 tars-agent가 코어를 링크하고 대화형 또는 헤드리스 프런트엔드를 고른다. 여러 세션을 맡는 데몬 agentd는 v1에 없다.

## 근거

- 본보기인 Claude Code가 이 모양이다. 터미널에서 실행하고, 세션은 파일로 남고, 여러 개가 필요하면 여러 번 띄운다.
- 데몬이 풀려던 문제가 사라진다. 승인 대기가 OS 스레드를 점유하는 것은 세션이 하나면 문제가 아니다. 런타임 풀과 세션 관리자도 필요 없다. "수십 세션에서 스레드 점유가 문제인가"라는 열린 질문을 닫는다.
- 격리가 공짜다. 한 세션의 스크립트가 컴파일러 abort를 밟아도 다른 세션은 다른 프로세스다.
- 메모리: 첫 VM 약 7 MB. 패널 여덟에 하나씩 띄워도 부담이 없다.
- macOS 개발 호스트에서 그대로 돈다. tars 고유 장치에 기대지 않는다.

## 데몬이 필요해지는 때

tars 터미널 제어 채널(tars.* 능력)이나 MCP 서버 방향을 만들 때다. 그때 agentd는 코어 위의 프런트엔드 하나로 얹고, 헤드리스 stream-json 이벤트 형식을 그대로 쓴다. 코어와 프런트엔드를 이벤트로 나누는 규칙(01 문서)이 이를 위한 것이다.
