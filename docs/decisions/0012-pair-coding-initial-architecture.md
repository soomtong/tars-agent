# 0012 초기 아키텍처는 페어 코딩으로

상태: 사용자 지시 (2026-11-12)

## 결정

- 초기 구간(M0 스파이크와 아키텍처 뼈대)은 페어 코딩으로 간다. tars-linux에서 쓴 방식(설명, 실행, 설명)을 가져온다.
- 단계마다 결정(사용자가 정할 디자인), 편집(구조를 결정짓는 코드), 기능(Claude가 채울 구현)을 나눠 공유하고 시작한다.
- 편집 주체: 능력 표(caps/table.zig)와 코어-프런트엔드 이벤트 타입은 사용자가 직접 편집한다. 나머지는 Claude가 넣고 사용자가 읽고 판단한다.
- M0 스파이크도 함께 만들고 버린다. 스파이크를 남기는 코드로 세우자는 Claude의 제안은 받지 않았다.
- 규칙의 정본은 CLAUDE.md다.

## 이유

- 사용자: "나는 아직 코딩 에이전트가 실제로 어떻게 동작하는지 완벽하게 이해하지 못하고 있거든. 그 부분을 M0에서 학습할 수 있는 기회로 삼자."
- 전체 아키텍처를 설계하고 방향을 잡는 데 페어가 도움이 된다는 것이 tars-linux의 경험이다.

## 바뀌는 것

- 이전 규칙 "설계 선택지를 계속 묻지 않고 추천안으로 정해 진행한다"는 초기 구간에서 멈춘다. 구조에 관한 결정은 사용자가 정한다. 사소한 선택은 계속 추천안으로 간다.
- M0의 목적에 학습이 더해진다. 스파이크의 순서와 크기는 증명할 것과 함께 배울 것을 기준으로 정한다.

## 페어로 다룰 경계 (제안, 순서는 진행하며 정한다)

1. 저장소 뼈대: build.zig, cyber 의존 고정과 링크
2. runtime 경계: runtime/cy.zig, eval과 CL_AWAIT 결과 타입
3. 능력 표: caps/table.zig의 항목 타입과 comptime 생성
4. 내부 메시지 형식: core/message.zig
5. 코어와 프런트엔드 사이의 이벤트와 명령 타입
6. loop 뼈대: 모델 호출, validate, eval, 승인, resume
