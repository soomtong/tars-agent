# 에이전트 루프 (CodeAct)

## 메시지 형식

- 역할: user, assistant
- assistant 블록: text, tool_use(name = run, input = { code })
- user 블록: text, tool_result(tool_use_id, content, is_error)
- 내부 공통 형식을 두고 provider 어댑터가 제공자 형식으로 변환한다.

## 한 턴의 절차

1. 시스템 프롬프트(언어 부분집합, 호스트 함수 사양, 규칙) + 히스토리 + run 도구 정의를 모델에 보낸다.
2. 응답에 run 블록이 있으면 code를 꺼낸다. 없으면 턴을 끝낸다.
3. 검증: cl_vm_validate로 세션 VM 위에서 컴파일만 한다. 실패하면 컴파일 오류 요약을 is_error 결과로 돌려주고 4로 가지 않는다.
4. 실행: 턴 연료(cl_vm_set_fuel)와 벽시계 타이머(cl_vm_interrupt)를 걸고 cl_vm_evalx로 실행한다. persist_main으로 함수, 타입, use 선언, main 지역 변수가 다음 eval로 이어진다.
5. 결과 조립: printer 콜백으로 모은 출력 + 마지막 표현식 값(res/res_t, cl_value_desc) + 오류. 상한으로 절단하고 절단 사실을 표시한다.
6. tool_result로 히스토리에 추가하고 1로 돌아간다.

## 실패는 모두 결과

- 컴파일 오류, panic(CL_ERROR_PANIC, 스택 트레이스 요약 포함), 중단(CL_ERROR_INTERRUPT: 연료 소진 또는 시간 초과), 권한 거부, 호스트 함수 오류가 각각 구분되는 문구로 돌아간다.
- panic이면 힙이 비워져 main 지역 변수가 사라진다. 결과에 "variables were reset"을 적어 모델이 알게 한다. 유지해야 할 상태는 호스트 함수(예: 작업 메모)에 둔다.
- 첫 eval 컴파일 실패 뒤에는 VM이 스스로 reset한다 (fork가 처리). 결과에 reset 사실을 적는다.
- 빈 출력은 ok 또는 실행 완료 요약으로 보정한다.

## 종료와 안전장치

- 최대 턴 수, 턴당 연료, 턴당 벽시계, 세션 토큰 예산
- 같은 코드가 N회 연속 실패하면 경고 결과, 계속되면 중단
- 사용자 인터럽트: cl_vm_interrupt를 다른 스레드에서 호출한다. 호스트 함수 안에서 막힌 경우는 못 끊으므로 그 함수가 자체 시간 제한과 취소 확인을 가진다 (03).
- max_tokens로 응답이 잘렸으면 잘린 코드는 실행하지 않고 오류로 알린다.

## 승인 대기

현재 런타임에는 호스트 함수 안에서 멈췄다가 임의 시간 뒤 재개하는 수단이 없다. 승인 대기는 호스트 함수가 동기적으로 블록하는 방식으로 한다 (VM당 OS 스레드 하나, 블록 중 VM은 그대로 대기). 세션 수십 개까지는 메모리상 가능하다 (VM당 약 2 MB). 이 방식의 한계가 실제 문제인지 본 뒤 스택형 Fiber 구현을 판단한다.

## 컴팩션

- 임계치에 도달하면 오래된 실행 결과를 요약으로 치환한다. 코드 블록은 남기고 출력만 줄이는 안을 먼저 본다.
- VM 상태(함수, 변수)는 히스토리와 별개로 살아 있으므로, 요약에 현재 정의된 이름 목록을 넣어 모델이 알게 한다.

## 서브에이전트 (후속)

- 별도 VM과 히스토리를 가진 하위 루프. 결과 요약만 상위에 반환한다.
