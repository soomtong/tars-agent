# 에이전트 루프

## 메시지와 히스토리

- 역할: user, assistant. assistant 블록은 thinking, text, tool_use(name = run, input = { code }). user 블록은 text, tool_result(tool_use_id, content, is_error).
- 히스토리는 덧붙이기만 한다. 이미 보낸 메시지를 고치거나 지우지 않는다. 사고 블록은 그것을 만든 대화 안에서만 유효하고, 앞부분을 고치면 프롬프트 캐시도 깨진다. 줄여야 할 때는 컴팩션으로 새 히스토리를 시작한다.
- assistant 응답의 content는 사고 블록을 포함해 받은 그대로 보관하고 그대로 되돌려 보낸다.

## 모델 요청 (Anthropic Messages API)

- 기본 모델은 claude-opus-5-5다. 설정 키 model로 바꾼다. 평가(M0)는 claude-sonnet-5-5, claude-haiku-5-5도 함께 잰다.
- 스트리밍만 쓴다. max_tokens 기본 64,000.
- thinking은 adaptive, 강도는 output_config.effort로 정한다 (기본 high, 설정 키 effort). budget_tokens, temperature, 응답 프리필은 쓰지 않는다. 현재 모델이 거부한다.
- tool_choice는 auto다. 강제 도구 선택은 현재 모델이 거부하므로 "행동은 run으로만 한다"를 시스템 프롬프트로 지시한다.
- run 도구는 strict 스키마({ code: string })와 eager_input_streaming을 켠다. 코드가 써지는 대로 화면에 보인다. 입력 JSON은 하네스가 직접 검증한다.
- 캐시: 렌더 순서는 tools, system, messages다. 시스템 프롬프트는 세션 동안 바이트 단위로 고정하고 끝에 cache_control을 둔다. 대화 쪽은 마지막 블록에 cache_control을 옮겨 가며 둔다. 시각, 작업 상태처럼 변하는 값은 시스템 프롬프트에 넣지 않는다.
- 세션 중 바뀌는 지시(모드 변경, 할 일 알림)는 시스템 프롬프트를 고치지 않고 messages에 system 역할 메시지를 덧붙인다. 캐시된 앞부분이 유지된다.
- 프로젝트 지시 파일(AGENTS.md)은 첫 user 메시지 앞에 붙인다. 시스템 프롬프트는 모든 프로젝트에서 같게 유지된다.

## 한 스텝의 절차

1. 요청을 보내고 스트림을 받는다. text와 코드를 프런트엔드에 흘린다.
2. stop_reason을 먼저 본다.
   - end_turn: 턴을 끝낸다.
   - tool_use: 3으로 간다. 한 응답에 run 블록이 여럿이면 순서대로 실행하고 결과를 user 메시지 하나에 모두 담는다.
   - max_tokens: 잘린 코드는 실행하지 않는다. 잘렸다는 오류 결과를 돌려주고 더 작은 단위로 쓰라고 알린다.
   - refusal: 실행하지 않는다. 사용자에게 거절 범주를 보이고 턴을 끝낸다.
   - pause_turn: 그대로 이어서 요청한다.
3. 검증: cl_vm_validate로 세션 VM 위에서 컴파일만 한다. 실패하면 컴파일 오류를 is_error 결과로 돌려주고 실행하지 않는다. 오류는 cl_vm_compile_error로 구조화해 받는다(종류, 메시지, 줄, 열, 표시 길이. 줄과 열은 0부터라 1을 더해 보인다). 모델에게는 요약 문자열(cl_vm_compile_error_summary, 이스케이프 코드 없음)을 주고 세션 기록에는 구조화한 필드를 남긴다. 컴파일러는 첫 오류에서 멈추므로 한 번에 오류 하나다.
4. 실행: 연료, 벽시계 타이머, 스택 상한, 메모리 상한을 걸고 cl_vm_evalx로 실행한다. CL_AWAIT로 돌아오면 타이머를 멈추고 승인을 받아 Future를 완료한 뒤 cl_vm_resume으로 이어 간다. 거부는 error.Denied로 완료, 취소는 resume하지 않고 버린다 (ADR 0011). persist_main으로 함수, 타입, use 선언, main 지역 변수가 다음 eval로 이어진다.
5. 결과 조립: printer 콜백으로 모은 출력, 마지막 표현식 값(res, res_t, cl_value_desc), 오류. 상한을 넘으면 03의 넘침 규칙을 따른다.
6. tool_result를 히스토리에 덧붙이고 1로 돌아간다.

기록 순서: 코드는 실행 전에, 능력 호출은 호출마다, 결과는 실행 뒤에 세션 파일에 쓴다. 프로세스가 죽어도 무엇을 하다 죽었는지 남는다.

## 실패는 모두 결과

루프는 스크립트 때문에 죽지 않는다. 실패는 종류마다 구분되는 문구로 돌아간다.

| 종류 | 원인 | VM 상태 |
|---|---|---|
| compile error | validate 실패 | 유지 |
| panic | CL_ERROR_PANIC. 스택 오버플로와 OutOfMemory 포함. 트레이스는 양 끝 20프레임 | 변수 초기화 |
| interrupted | 연료 소진, 벽시계 초과, 사용자 인터럽트 | 변수 초기화 |
| denied | 사용자가 승인을 거부 | 유지 (오류 값으로 돌아간다) |
| capability error | 능력이 오류 값을 반환 | 유지 |

- 변수가 초기화된 경우 결과 끝에 variables were reset을 붙인다. 함수와 타입 선언은 남는다. 남겨야 할 값은 memo 능력에 둔다.
- 첫 eval의 컴파일 실패나 할당 실패 뒤에는 VM이 스스로 reset한다 (fork가 처리). 결과에 reset 사실을 적는다.
- 빈 출력은 ok와 실행 요약(능력 호출 수, 걸린 시간)으로 채운다.

## 제공자 오류

- 429, 5xx, 529, 연결 끊김: 지수 백오프로 재시도한다 (기본 5회, retry-after 존중). 스트림 중간에 끊기면 그 응답을 버리고 같은 요청을 다시 보낸다.
- 400, 401, 403, 404: 재시도하지 않고 사용자에게 보인다. 히스토리는 요청 전 상태로 둔다.
- 컨텍스트 초과: 컴팩션을 한 번 하고 다시 보낸다.

## 한도

- 턴당 스텝 수 (기본 50), 스텝당 연료, 스텝당 벽시계 (기본 120초), 세션 토큰 예산 (선택)
- 같은 코드가 3회 연속 같은 오류로 실패하면 결과에 경고를 붙이고, 5회면 턴을 끝내고 사용자에게 넘긴다.
- 헤드리스는 --max-steps, --max-budget-usd를 받는다.

## 인터럽트

- Esc 또는 Ctrl-C 한 번: 스트림을 받는 중이면 요청을 끊고, 스크립트 실행 중이면 cl_vm_interrupt를 부르고 취소 플래그를 세운다.
- cl_vm_interrupt는 능력 함수 안에서 막힌 호출을 못 끊는다. 막힐 수 있는 능력(프로세스 대기, HTTP)은 취소 플래그를 스스로 확인하고 돌아온다 (03). 승인 대기는 VM 밖이라 해당하지 않는다 (ADR 0011, 도입 전까지는 승인 대기도 플래그를 확인한다).
- 끊긴 턴도 히스토리에 남는다. 실행하지 못한 tool_use에는 interrupted 결과를 채워 메시지 짝을 맞춘다.

## 컴팩션

- 입력 토큰이 임계치(컨텍스트 창의 80%)를 넘거나 사용자가 /compact를 치면 한다.
- 방식: 모델에게 지금까지의 요약을 쓰게 하고, 그 요약을 첫 user 메시지로 하는 새 히스토리를 시작한다. 옛 히스토리는 세션 파일에 남고 요청에서만 빠진다. 히스토리 중간을 고치는 방식은 쓰지 않는다.
- 요약에 반드시 넣는 것: 사용자의 원래 요청과 이후 지시, 고친 파일 목록, 할 일 목록, memo 키 목록, VM에 살아 있는 함수와 변수 이름 (호스트가 덧붙인다).
- VM은 컴팩션과 무관하게 살아 있다.

## 세션 재개 (ADR 0008)

- --continue (이 디렉터리의 마지막 세션), --resume <id>.
- 히스토리는 세션 파일에서 복원한다. VM 상태는 복원하지 않는다. 과거 코드를 다시 실행하면 부작용도 다시 일어나기 때문이다.
- 재개한 세션의 첫 요청에 "VM이 새로 시작됐다. 이전에 정의한 함수와 변수는 없다"는 system 메시지를 덧붙인다. memo 값과 할 일 목록은 세션 파일에서 복원한다.
