# 에이전트 루프

## 메시지 형식

- 역할: user, assistant
- assistant 콘텐츠 블록: text, tool_use(id, name, input)
- user 콘텐츠 블록: text, tool_result(tool_use_id, content, is_error), image
- 내부 공통 형식을 두고 provider 어댑터가 제공자 형식으로 변환한다.

## 루프 의사 절차

1. 시스템 프롬프트 + 히스토리 + 도구 정의를 모델에 보낸다.
2. 스트리밍으로 텍스트를 frontend에 흘리고 tool_use 블록을 모은다.
3. stop_reason이 tool_use이면 모든 블록을 실행한다.
   - 읽기 전용 도구는 병렬, 편집과 셸은 순서대로.
   - 각 호출은 정확히 하나의 tool_result를 만든다 (실패, 거부, 취소 포함).
4. tool_result를 하나의 user 메시지로 묶어 히스토리에 추가하고 1로 돌아간다.
5. stop_reason이 end_turn이면 종료한다.

## 종료와 안전장치

- 최대 턴 수, 최대 도구 호출 수, 토큰 예산 상한
- 동일 호출 반복 감지: 같은 이름과 인자로 N회 연속 실패하면 모델에 경고 결과를 돌려주고, 계속되면 중단
- 사용자 인터럽트: 실행 중 프로세스를 종료하고 "cancelled by user" 결과를 남긴 뒤 입력 대기
- max_tokens로 응답이 잘린 경우: 잘린 tool_use는 실행하지 않고 오류 결과로 알린다

## 컴팩션

- 임계치(예: 컨텍스트 창의 80%) 도달 시 오래된 도구 결과를 요약으로 치환한다.
- 요약 후에도 최근 N턴과 시스템 프롬프트는 원문을 유지한다.
- 컴팩션 사실은 세션 로그에 기록한다.

## 서브에이전트 (후속 단계)

- 독립 히스토리를 가진 하위 루프. 결과 요약만 상위에 반환한다.
- 도구 집합과 권한 모드를 에이전트 정의로 제한한다.
