# 권한과 보안

두 층이다. 1층은 스크립트가 무엇에 닿을 수 있는가(런타임 구성), 2층은 닿는 호출을 허용할지(정책 게이트).

## 1층: 런타임 구성 (샌드박스)

- libcyber를 -Dffi=false 로 빌드한다. tcc도 링크되지 않아 LGPL 문제도 없다 (라이선스 조건의 전제).
- 로더에서 os 모듈은 원래 없고, c 모듈은 걸러낸다.
- CLEvalConfig.deny_raw_ptrs = true. use c 없이도 as[Ptr[int]] 8 로 임의 주소를 읽던 경로를 막는다.
- 메모리 상한은 cl_vm_initx 로 호스트 할당자를 주어 걸 수 있다.
- 실행 상한: 턴당 연료(cl_vm_set_fuel), 벽시계(타이머 스레드가 cl_vm_interrupt).
- 컴파일러 abort 경로가 남아 있을 수 있으므로 스크립트 실행 프로세스를 분리하는 안을 평가한다 (P0).
- 방식 B(Cyber CLI)에서는 os와 FFI가 열려 있어 1층 보장이 약하다. 프로토타입 한정으로만 쓴다.

## 2층: 정책 게이트

- 호스트 함수 본체가 실행 직전에 게이트를 부른다. 정책은 core에 있고 UI는 승인만 그린다.
- 분류: 호스트 함수 표의 읽기/파괴 표시가 1차. shell은 명령 문자열을 파싱한 2차 분류.
  - 읽기 전용으로 알려진 명령(ls, cat, rg, fd, git status 등)은 allow 후보
  - 리다이렉션, 쓰기 파이프, rm, mv, chmod, 설치, sudo는 ask
  - 파싱 불가나 복합 명령(서브셸, eval)은 ask
- 결과: allow / ask / deny. 모드별 기본: plan(읽기만 allow), default(읽기 allow, 나머지 ask), auto(규칙에 맞는 것만 allow), yolo(명시 옵션)
- 승인 기억: 같은 패턴을 세션 또는 프로젝트 단위로 파일에 저장. 사용자가 직접 편집 가능
- 거부도 결과: 호스트 함수가 permission denied by user 오류를 반환한다. 스크립트는 오류 값으로 이어 갈 수 있다.
- 한 스크립트가 여러 쓰기를 하는 경우를 위해 스크립트 단위 사전 요약 승인(계획 보여주기)을 후속으로 검토한다.

## 보호 규칙

- 하네스가 시작하지 않은 프로세스는 종료하지 않는다.
- 작업 디렉터리 밖 쓰기는 기본 ask. 시스템 경로(/etc, /boot, /usr 등)는 기본 deny.
- 비밀 값(환경 변수, 키 파일)은 로그에 남기지 않는다. 마스킹 규칙 필요.
- tars 규칙 승계: 부팅은 에이전트나 네트워크 때문에 막히지 않는다.

## 헤드리스

- ask가 발생하면 기본은 deny로 처리하고 로그에 남긴다.
- 정책 파일 없이는 쓰기 함수를 실행하지 않는다.

## 프롬프트 인젝션

- 파일, 웹, MCP 결과는 데이터이며 지시가 아니다. 시스템 프롬프트에 명시한다.
- 외부 출처 결과가 개입한 파괴적 호출은 자동 허용에서 제외한다.
