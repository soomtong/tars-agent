# 세션 기록과 관측

## 세션 파일

세션 기록, 감사 로그, 리플레이 재료는 한 파일이다. 따로 두면 어긋난다.

- 형식: JSON Lines, 덧붙이기만 한다. 줄 머리는 아래 "줄 머리".
- 위치: $XDG_STATE_HOME/tars-agent/sessions/<작업 디렉터리 해시>/<세션 ID>.jsonl (기본 ~/.local/state). 권한 0600.
- 곁 디렉터리 <세션 ID>/: out/ (넘침 파일), files/ (쓰기 전 보관본), crash/ (죽기 직전의 스크립트).

| type | 내용 |
|---|---|
| session | 버전, 제공자 항목, 모델, 프로파일, 도구 모드(codeact, direct), 작업 디렉터리, cyber 버전, 부모 세션(재개 시) |
| user | 사용자 입력. steering 입력은 히스토리에 붙인 시점에 쓴다 |
| assistant | 응답 content 그대로 (사고 블록 포함), 받은 stop_reason과 내용에서 다시 계산한 끝난 이유(10), usage. 쓰는 때(검증 전인지)는 정하지 않았다. 검증 중에 죽은 run의 짝 맞추기와 함께 02 열린 것 3에서 정한다 |
| run | tool_use_id, 코드, validate 결과. 실행 전에 쓴다 |
| cap | 능력, 인자 요약, 결정(allow, ask_allowed, ask_denied, deny. 06과 같은 값), 근거(맞은 규칙, 모드, 보호 규칙, headless), 외부 입력 표시를 세웠는지, 걸린 시간, 결과 크기, 오류 |
| result | tool_use_id, 결과 본문, 실패 종류, 연료(fuel) 사용량, 걸린 시간. crashed 결과는 재개할 때 쓴다 (02) |
| notice | 하네스 알림의 본문 (모드 변경, 할 일 알림, 재개 알림. 10). user 메시지에 붙인 시점에 쓴다 |
| memo, todo | 호스트 상태 변경 |
| compact | 요약, 새 히스토리의 시작 seq, 읽은 파일과 고친 파일의 누적 목록 |
| error | 제공자 오류, 재시도, 재개 때 잘라 낸 찢긴 꼬리 (아래 "쓰기와 복구") |

- 비밀은 쓰기 전에 가린다 (05).
- 재개는 이 파일에서 히스토리, memo, todo, 파일 상태, 외부 입력 표시(그것을 세운 cap 줄이 하나라도 있으면, 05)를 복원한다. user 메시지 하나는 이어진 result, notice, user 줄을 seq 순서로 모아 되살린다. 줄을 쓴 순서가 메시지 안의 블록 순서다.
- 형식에 버전을 둔다. 읽을 수 없는 버전의 세션은 재개를 거부하고 이유를 말한다.

### 줄 머리 (ADR 0030)

~~~text
{"v":1,"seq":7,"ts":1763600000000,"type":"run",...,"crc":"1a2b3c4d"}
~~~

- 앞의 네 필드는 이 순서로 고정한다. v는 형식 버전, seq는 0부터 1씩, ts는 유닉스 밀리초, type은 위 표의 것이다. type의 필드가 뒤따른다.
- crc는 줄 시작부터 줄의 마지막 `,"crc"` 바로 앞까지의 바이트에 대한 CRC32C(Castagnoli)이고 소문자 16진수 8자리다. 줄 끝은 `}`와 줄바꿈이다.
- 줄 하나는 4 MiB까지다. 넘는 본문은 out/에 두고 줄에는 경로를 적는다.
- 더 새 v의 세션은 재개하지 않는다. 읽기 도구(stats, 리플레이)는 모르는 type을 건너뛴다.

### 쓰기와 복구 (ADR 0030)

- 줄 하나는 O_APPEND로 연 파일에 write 한 번으로 쓴다. write가 끝난 줄은 프로세스가 죽어도(kill -9 포함) 남는다. run 줄을 실행 전에 쓰는 규칙(02)은 이것에 기댄다.
- fsync는 턴을 닫는 줄 뒤에만 한다: 턴의 마지막 assistant 줄, interrupted와 crashed 결과 줄, compact 줄, session 줄. 기계가 멈추면 마지막 턴의 일부를 잃을 수 있다.
- 새 세션은 `<세션 ID>.jsonl.tmp`에 session 줄을 쓰고 fsync한 뒤 rename하고 디렉터리를 fsync한다. 반쯤 만들어진 세션은 목록에 보이지 않는다.
- 재개할 때 파일을 끝에서부터 본다. 마지막 줄이 줄바꿈 없이 끝나거나 crc가 맞지 않고 그 뒤에 줄이 없으면 찢긴 꼬리다. 그 줄을 잘라 내고(truncate) 잘라 낸 바이트 수를 error 줄로 남긴 뒤 이어 간다. 그 다음에 크래시 결과 채우기(02)를 한다.
- 깨진 줄 뒤에 온전한 줄이 있거나 seq가 이어지지 않으면 손상이다. 재개를 거부하고 줄 번호를 말한다. 읽기 도구는 깨진 줄을 건너뛰고 그 수를 보인다.

### 잠금 (ADR 0030)

- 세션 하나에 쓰는 프로세스는 하나다. 쓰기 전에 `<세션 ID>/lock`에 flock(LOCK_EX, LOCK_NB)을 잡고 pid를 적는다. 프로세스가 사는 동안 쥐고, 프로세스가 끝나면 커널이 푼다.
- 잡지 못하면 2초 동안 다시 시도한 뒤 재개를 거부하고 잠금을 쥔 pid를 말한다. --continue와 --resume이 같다.
- 읽기 도구(stats, 리플레이, 세션 목록)는 잠그지 않는다.

## 리플레이

- 모의 provider가 세션 파일의 assistant 줄을 순서대로 돌려준다. 능력은 실제로 실행하거나, cap 줄과 result 줄을 대조만 한다.
- 용도 둘: 루프 회귀 테스트 (test/의 시나리오), 죽은 세션의 재현.

## 비용과 통계

- 요청마다 입력, 출력, 캐시 쓰기, 캐시 읽기 토큰과 지연을 기록한다. 가격표는 모델별로 설정에 두고 비용을 계산한다.
- /cost와 헤드리스 json 출력이 세션 합계를 보인다.
- tars-agent stats: 세션 파일들을 읽어 능력별 호출 수, 오류율, 평균과 최대 결과 크기, 실패 종류별 스텝 비율을 낸다. 컴파일 오류 비율은 Cyber 안내 문구를 고칠 근거다.
- stats는 죽은 run의 비율도 낸다(01 "죽는 비율을 재는 법"). crashed 결과 줄과 함께, 재개하지 않은 세션의 결과 없는 run 줄도 죽은 run으로 센다. 같은 tool_use_id는 한 번만 센다. 검증 중에 죽어 run 줄이 없는 경우를 어떻게 가를지는 02 열린 것 3을 따른다.

## 하지 않는 것

- 원격 전송, 텔레메트리, OpenTelemetry. 기록은 기계 밖으로 나가지 않는다.
