# 세션 기록과 관측

## 세션 파일

세션 기록, 감사 로그, 리플레이 재료는 한 파일이다. 따로 두면 어긋난다.

- 형식: JSON Lines, 덧붙이기만 한다. 줄마다 type, ts, seq.
- 위치: $XDG_STATE_HOME/tars-agent/sessions/<작업 디렉터리 해시>/<세션 ID>.jsonl (기본 ~/.local/state). 권한 0600.
- 곁 디렉터리 <세션 ID>/: out/ (넘침 파일), files/ (쓰기 전 보관본), crash/ (죽기 직전의 스크립트).

| type | 내용 |
|---|---|
| session | 버전, 모델, 프로파일, 작업 디렉터리, cyber 버전, 부모 세션(재개 시) |
| user | 사용자 입력 |
| assistant | 응답 content 그대로 (사고 블록 포함), stop_reason, usage |
| run | tool_use_id, 코드, validate 결과. 실행 전에 쓴다 |
| cap | 능력, 인자 요약, 결정(allow/ask-허용/ask-거부/deny, 근거 규칙), 걸린 시간, 결과 크기, 오류 |
| result | tool_use_id, 결과 본문, 실패 종류, 연료 사용량, 걸린 시간 |
| system | 덧붙인 system 메시지 (모드 변경 등) |
| memo, todo | 호스트 상태 변경 |
| compact | 요약, 새 히스토리의 시작 seq |
| error | 제공자 오류, 재시도 |

- 비밀은 쓰기 전에 가린다 (05).
- 재개는 이 파일에서 히스토리, memo, todo, 파일 상태를 복원한다.
- 형식에 버전을 둔다. 읽을 수 없는 버전의 세션은 재개를 거부하고 이유를 말한다.

## 리플레이

- 모의 provider가 세션 파일의 assistant 줄을 순서대로 돌려준다. 능력은 실제로 실행하거나, cap 줄과 result 줄을 대조만 한다.
- 용도 둘: 루프 회귀 테스트 (test/의 시나리오), 죽은 세션의 재현.

## 비용과 통계

- 요청마다 입력, 출력, 캐시 쓰기, 캐시 읽기 토큰과 지연을 기록한다. 가격표는 모델별로 설정에 두고 비용을 계산한다.
- /cost와 헤드리스 json 출력이 세션 합계를 보인다.
- tars-agent stats: 세션 파일들을 읽어 능력별 호출 수, 오류율, 평균과 최대 결과 크기, 실패 종류별 스텝 비율을 낸다. 컴파일 오류 비율은 Cyber 안내 문구를 고칠 근거다.

## 하지 않는 것

- 원격 전송, 텔레메트리, OpenTelemetry. 기록은 기계 밖으로 나가지 않는다.
