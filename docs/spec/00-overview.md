# 개요

## 목표

- tars-linux 안에서 동작하는 내장 AI 에이전트를 만든다.
- 에이전트는 도구 호출을 JSON으로 나열하지 않고 Cyber 스크립트를 써서 실행한다 (CodeAct 방식). 도구는 호스트가 Cyber 함수로 열어 준 것이다.
- 모델이 세계와 접촉하는 통로를 하네스가 안전하고 예측 가능하게 운영한다. 실패는 모두 결과로 돌아가고, 권한 판단은 코어에 둔다.
- 스킬이나 별도 학습 문서 주입 없이, 모델이 보는 것은 시스템 프롬프트의 도구 사양과 실행 결과뿐이다.

## 비목표

- 자체 모델 학습 또는 호스팅
- 다중 사용자 서버 운영
- GUI. 화면은 tars terminal이 그린다
- 대화형 TTY 프로그램(vim 등) 직접 제어

## 대상 환경 (확인된 사실)

출처: soomtong/tars-linux 0.2.0, soomtong/cyber(fork) 0.4.4.

- tars-linux는 직접 빌드한 Linux 커널 위에 Zig로 만든 init(PID 1)과 터미널(DRM/KMS + ghostty-vt)을 올리고 fish로 간다. 배포판이 아니다.
- 대상 아키텍처는 x86_64만이다. 개발 호스트는 Apple Silicon macOS이고 빌드는 컨테이너 안에서 한다.
- 바닥 라이브러리는 Debian glibc를 통째로 싣는다. 개별 유틸리티는 sha256을 고정한 공식 미리 빌드 바이너리를 쓰고 소스 빌드는 하지 않는다.
- 개발 도구 층(devlayer)이 squashfs로 /usr에 겹쳐진다. 여기에 이미 cyber 0.4.4(cyber-linux-x64.tar.gz)가 들어 있고, 실행 파일이 옆의 src/ 디렉터리를 읽는다.
- 부팅은 네트워크 유무와 무관하게 평소대로 끝나야 한다 (tars 결정). 에이전트는 부팅 경로를 막지 않는다.
- Cyber는 fubark/cyber의 fork다. upstream은 2025-12 이후 멈췄고 fork가 Zig 0.17, 임베딩 API, 중단/연료 상한을 직접 유지한다.

## 문서 규약

- 문서와 주석에 강조용 ** 를 쓰지 않는다.
- 커밋 메시지는 접두사 없이 첫 글자 대문자, 80자 이내.
- 새 결정은 docs/decisions에 파일로 남기고 MEMORY.md에 한 줄만 추가한다.

## 용어

- 하네스: 모델 호출, 스크립트 실행, 권한, 로그를 담당하는 프로그램 전체
- agentd: 하네스 프로세스의 가칭
- 호스트 함수: 하네스가 Cyber 스크립트에 열어 주는 함수. 이 프로젝트에서 도구의 실체다
- 턴: 모델 호출 한 번과 그 결과로 실행한 스크립트 묶음
- 세션: 하나의 대화 히스토리와 하나의 Cyber VM, 관련 로그
