# 요구사항 목록과 추적

요구는 00~11, 13 문서와 ADR에 흩어져 있다. 이 문서는 요구를 한 줄씩 모아 근거(명세 절, ADR), 할 일의 단계(docs/TODO.md), 확인 방법을 잇는다. 요구의 정본은 근거 문서이고, 이 문서는 색인이다. 근거가 바뀌면 이 문서의 줄을 고친다.

## 읽는 법

- ID: R-영역-번호. 영역은 LOOP(루프), PROV(제공자), RUN(런타임), CAP(능력 시스템), TOOL(내장 능력), PERM(권한), SBX(샌드박스), SEC(비밀과 인젝션), SESS(세션), COMP(컴팩션), CTX(프롬프트와 지시 파일), FE(대화형), HL(헤드리스), OBS(관측), DIST(빌드와 배포), EVAL(평가), NF(비기능).
- 근거의 숫자는 docs/spec의 문서 번호다.
- 단계: TODO의 M0~M6, C(cyber 작업 줄기). 단계가 없으면 "없음".
- 확인: 아래 표기를 쓴다. "간접"은 게이트나 테스트가 그 동작을 지나가지만 그것을 따로 보지 않는다는 뜻이다.

## 코어-프런트엔드 이벤트 타입의 요구

이벤트 타입과 명령 타입은 사용자가 직접 편집한다(ADR 0012). 아래는 타입을 정하지 않고 요구만 모은 체크리스트다.

방향과 모양

- [ ] 이벤트는 코어에서 프런트엔드로, 명령은 프런트엔드에서 코어로 간다. 코어는 터미널을 만지지 않는다 (01).
- [ ] 이벤트 하나의 tagged union과 명령 타입을 둔다. 콜백 구조체로 잇지 않는다 (ADR 0030 가져오지 않는 것).
- [ ] stream-json은 이 이벤트를 줄마다 쓴 것이다. 편집기, 후속의 agentd, tars 게이트 스크립트가 이 형식으로 붙는다 (06, ADR 0004). json의 v처럼 버전과 "더하기만" 규칙을 stream-json에도 둘지 정한다 (06은 json 객체에만 적는다).
- [ ] text와 json 출력은 같은 결과에서 만든다 (06).
- [ ] ACP의 session/update(message chunk, tool_call, tool_call_update, plan)와 session/request_permission으로 손실 없이 옮겨진다 (ADR 0029).
- [ ] ACP의 tool_call을 run 스크립트 하나에 맞출지 능력 호출 하나에 맞출지 정한다 (ADR 0029).
- [ ] ACP 클라이언트가 fs/*, terminal/*을 제공할 때 능력 본체를 바깥에 위임하고 비동기로 받는 길(미완료 Future 경로)과 맞는지 본다 (ADR 0029).

모델 출력

- [ ] 글 조각과 사고 조각을 흘려 보낸다 (02 절차 1, ADR 0015의 내부 스트림 이벤트).
- [ ] run의 코드가 써지는 대로 보인다(eager_input_streaming) (02).
- [ ] 코드를 접은 한 줄 요약(능력 호출 목록)을 그릴 재료가 있다 (06).
- [ ] refusal이면 거절 범주를 보인다 (02 절차 2).

도구 카드 (ADR 0030 결정 6)

- [ ] 도구 카드의 임시(스트리밍 중)와 확정 구분.
- [ ] 결과 종류: 02의 실패 종류 전부(ok, compile_error, panic, interrupted, denied, capability_error, crashed)와 능력 호출의 상태(ok, error, denied, cancelled).
- [ ] 턴 끝에 열린 카드를 닫는다(인터럽트, 크래시 재개 포함).
- [ ] 결과 끝의 안내(최상위 변수 초기화, 세션 reset, 같은 오류 반복 경고, 넘침 파일 경로)를 보일 수 있다 (02, 03).

승인과 질문

- [ ] 승인 요청은 한 번에 하나다 (ADR 0016). 요청 묶음을 다루지 않는다.
- [ ] 승인 요청이 담는 것: 능력과 인자, fs.edit의 diff, proc의 명령 전체, 그 호출을 낸 스크립트의 줄, 요청의 출처(어느 run, 어느 능력 호출) (05 승인 프롬프트, ADR 0030 결정 6).
- [ ] 승인 답 명령: 다섯 선택지(한 번 허용, 세션 동안 같은 패턴, 항상 허용, 거부, 거부하고 지시 입력). 5번은 사용자의 글을 싣는다 (05).
- [ ] 승인 대기 중의 취소(Esc)는 resume하지 않고 버리는 명령이다 (ADR 0011).
- [ ] 대화형과 헤드리스 stream-json이 같은 승인 경로를 쓴다 (ADR 0011). 헤드리스에서 ask는 deny로 기록된다 (05).
- [ ] ui.ask의 질문(선택지 2~4개와 직접 입력)이 이벤트로 나가고 답이 명령으로 돌아오는지는 03 열린 것 3에 달렸다.
- [ ] 프로젝트 설정(allow 규칙, 프로파일)의 처음 수락 요청 (05).

입력과 steering

- [ ] 사용자 입력 명령. 실행 중에도 받는다 (02 실행 중 입력).
- [ ] steering 큐의 상태(대기 수, 내용)를 코어가 이벤트로 낸다 (02).
- [ ] 인터럽트로 턴을 끊으면 큐에 남은 입력을 프런트엔드의 입력 줄로 돌려준다 (02).
- [ ] 인터럽트 명령(Esc, Ctrl-C)과 종료 (02, 06).

상태와 알림

- [ ] 상태 줄의 재료: 모드, 모델, 컨텍스트 사용률, 세션 비용 (06).
- [ ] 모드 변경 명령(Shift+Tab, /mode)과 바뀐 모드 (05).
- [ ] 할 일 목록(ui.todo)을 그린다 (04).
- [ ] 시작 알림: 샌드박스 없음, rg 없음으로 fs.search를 싣지 않음, AGENTS.md 상한 초과 (04, 05, 06).
- [ ] 컴팩션 시작과 끝, 재개 안내(VM 새 시작, crashed 결과와 crash/ 보관), 제공자 재시도, 캐시 경고 (02, 06, 07).
- [ ] 슬래시 명령(/compact, /clear, /resume, /model, /cost, /permissions)이 코어 명령으로 가는지 프런트엔드 안에서 끝나는지 (06).
- [ ] 멈춘 이유: 06의 stop 값(end_turn, error, refusal, max_steps, budget, repeated_error, permission_denied, interrupted)을 ACP의 멈춘 이유와 맞춘다 (ADR 0030 결정 6).
- [ ] 세션 파일의 줄(07)과 이벤트의 관계. 같은 사건이 두 곳에 쓰이므로 이름과 값(결정 allow, ask_allowed, ask_denied, deny 등)을 맞춘다 (06, 07).
