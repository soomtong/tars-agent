# 능력 시스템

도구는 호스트가 Cyber에 열어 준 능력 함수다. 모델이 능력에 대해 아는 것은 시스템 프롬프트의 사양과 실행 결과뿐이므로, 사양과 오류 문구가 품질을 정한다.

## 능력 표 (단일 소스)

Zig comptime 표의 한 항목이 능력 하나다.

~~~text
name     fs.read
params   path: str, offset: int = 0, limit: int = 2000
returns  !str
grade    read            (pure | read | write | exec | net | ui)
doc      모델이 읽는 사양 (영어)
impl     Zig 함수. VM을 모른다
~~~

표에서 Cyber 선언과 바인딩, 프롬프트 사양, JSON Schema, 등급 표를 생성한다 (01, ADR 0006).

## 사양 쓰는 법

사양은 문서가 아니라 모델이 읽는 계약이다. 영어, 짧은 문장으로 쓴다.

1. 한 문장 요약
2. 언제 쓰고 언제 쓰지 않는지. 이웃 능력과의 경계 (예: 내용 검색은 fs.search, proc.exec로 rg를 부르지 않는다)
3. 결과 모양과 상한
4. 전제와 부작용 (예: fs.edit는 같은 세션에서 fs.read가 선행해야 한다)
5. 호출 예 한두 줄

사양 전체가 요청마다 실리므로 토큰 예산을 둔다: Cyber 부분집합 안내 4,000 토큰, 능력 사양 3,000 토큰. 예산을 넘는 능력은 한 줄 요약만 싣고 help(name)로 전체 사양을 조회하게 한다.

## 이름과 모듈

- 이름은 모듈.동사 꼴이다. 모듈은 fs, proc, net, ui, memo, clock.
- 세션 시작 때 호스트가 머리말 스크립트를 한 번 eval해 use 선언을 넣는다. persist_main이 이를 이어 주므로 모델은 use를 쓰지 않는다.
- 호스트 로더가 허용하는 모듈은 cyber 표준 모듈 core, math, json, regex, time과 위의 호스트 모듈뿐이다. c, io, meta, cy, test는 로드를 거부한다. 순수 계산은 표준 모듈의 몫이고 능력으로 만들지 않는다 (ADR 0010).

## 검증

- 정적 타입이 1차 검증이다. 타입 오류는 validate 단계에서 컴파일 오류로 돌아간다.
- 값 검증(경로 범위, 크기, 패턴 문법)은 본체가 하고 오류 문구로 가르친다. 오류는 무엇이 틀렸는지와 다음에 할 일을 함께 말한다. 예: old text matches 3 places; add surrounding lines to make it unique, or pass replace_all = true.
- 반환은 !T다. 실패는 오류 값으로 돌아가 스크립트가 처리할 수 있다. 처리하지 않으면 panic이 되어 결과로 돌아간다.

## 본체 작성 규칙

- 본체는 Zig 값만 다룬다. Cyber 값 변환과 해제는 생성된 바인딩이 한다. 값으로 받은 str, []T는 바인딩이 본체 호출 뒤 cl_str_deinit, cl_slice_deinit으로 해제한다.
- 모든 실패 경로는 오류로 반환한다. @panic, unreachable, abort로 프로세스를 죽이지 않는다.
- 실행 직전에 권한 게이트를 부른다 (05). 게이트 호출도 바인딩 층에 있어 본체가 빠뜨릴 수 없다.
- 막힐 수 있는 본체는 자체 시간 제한을 갖고 취소 플래그를 100 ms 간격 이하로 확인한다.
- 경로는 작업 디렉터리 기준 상대 경로로 받고 돌려준다. 내부에서는 정규화한 절대 경로로 정책을 판정한다 (심볼릭 링크를 따라간 뒤).
- 부작용만 있는 능력도 완료 요약을 돌려준다. 빈 결과는 없다.
- 호출마다 감사 기록을 남긴다: 능력, 인자 요약, 결정, 걸린 시간, 결과 크기 (07).

## 결과 상한과 넘침

- 능력 하나의 반환값 상한과 스크립트 결과 전체의 상한을 따로 둔다 (기본 각각 30,000자, 20,000자).
- 넘치면 자르기만 하지 않는다. 전체를 세션 디렉터리의 파일로 쓰고, 결과에는 앞 200줄과 뒤 50줄, 생략된 줄 수, 파일 경로를 담는다. 모델은 fs.read나 fs.search로 필요한 부분을 다시 본다.
- 바이너리는 내용 대신 종류와 크기를 돌려준다.
- 사양에 지시한다: 큰 결과는 스크립트 안에서 줄여 필요한 것만 출력하라.

## 파일 상태 추적

- 세션은 읽은 파일의 경로, mtime, 크기를 기억한다.
- fs.edit와 기존 파일에 대한 fs.write는 읽은 적이 없거나 읽은 뒤 바뀐 파일을 거부하고 다시 읽으라고 알린다. 사용자가 편집기에서 고친 것을 덮어쓰지 않기 위해서다.
- 쓰기 전에 원본을 세션 디렉터리에 한 번 보관한다 (턴마다 파일당 처음 한 번). 되돌리기(/rewind)의 재료다 (06).

## 프로세스 실행

- 능력은 둘이다. proc.exec는 인자 배열을 받아 셸 없이 실행한다. proc.sh는 문자열을 /bin/sh -c로 실행한다 (04).
- 긴 작업은 proc.start가 작업 ID를 돌려주고 proc.output, proc.kill로 다룬다. 종료 대상은 하네스가 시작한 작업으로 한정한다.
- 시간 제한에 걸리면 지금까지의 출력과 timed out을 돌려준다. 프로세스 그룹째 종료한다.
- 환경: 작업 디렉터리 고정, stdin은 닫는다, TERM=dumb, 페이저와 색을 끈다. 하네스의 비밀 값(ANTHROPIC_API_KEY 등)은 자식 환경에서 지운다.
- 세션이 끝나면 하네스가 시작한 프로세스를 모두 정리한다.

## 병렬

- v1은 스크립트의 spawn을 막는다 (연료가 스레드마다 따로 세어지고, 승인 프롬프트가 겹친다).
- 병렬이 필요해지면 호스트가 제공한다: 읽기 등급 호출 여럿을 한 번에 받는 능력을 후속으로 둔다.

## 하네스가 지원하지 않는 것

- 대화형 TTY 프로그램: stdin을 닫아 비대화형으로 만든다. 입력을 기다리면 시간 제한으로 끝난다
- 외부 세션(DB 셸) 유지: 후속
- 사람 입력이 필요한 흐름(OAuth): 후속
