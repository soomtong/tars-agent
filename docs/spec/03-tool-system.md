# 능력 시스템

도구는 호스트가 Cyber에 열어 준 능력 함수다. 모델이 능력에 대해 아는 것은 시스템 프롬프트의 사양과 실행 결과뿐이므로, 사양과 오류 문구가 품질을 정한다.

## 능력 표 (단일 소스)

Zig comptime 표의 한 항목이 능력 하나다.

~~~text
name     fs.read
params   path: str, offset: int = 0, limit: int = 2000
returns  !str
grade    read            (pure | read | write | exec | net | ui)
doc      모델이 읽는 사양 (영어)
impl     Zig 함수. VM을 모른다
~~~

표에서 Cyber 선언과 바인딩, 프롬프트 사양, JSON Schema, 등급 표를 생성한다 (01, ADR 0006).

위 params와 returns는 모델이 보는 시그니처다. `= 0`은 생략할 수 있는 인자와 그 값을 뜻하는 표기이고 Cyber 문법이 아니다. 바인딩 함수의 실제 선언은 이와 다르다 (아래 절).

## 모델이 보는 시그니처와 바인딩

능력 하나는 Cyber 쪽에서 선언 둘이다. 호스트 모듈의 `#[bind]` 함수와 모델이 부르는 동기 래퍼다. 둘 다 호스트 로더가 그 모듈 이름(`fs`, `proc` 등)에 돌려주는 모듈 소스에 있다 (08, ADR 0011). 머리말은 세션 시작 때 한 번 eval하는 스크립트이고 이 모듈들의 use 선언만 넣는다 (아래 "이름과 모듈"). 검토 문서는 래퍼를 머리말의 래퍼라고 부른다. 바인딩 함수의 이름은 프롬프트에 싣지 않는다.

~~~cy
#[bind] fn read_async(path str) -> Future[!str]
fn read(path str) -> !str:
    return read_async(path).await()
~~~

확인된 사실

- Cyber에는 기본값 매개변수가 없다. `fn f(a int, b int = 2)`는 ``ParseError: Expected `,`.``이고 `#[bind]` 함수도 같다 (08, 검토 문서 3.2).
- 이름이 같고 매개변수 수가 다른 함수를 한 모듈에 둘 수 있다. `fs.read(path)`와 `fs.read(path, offset, limit)`가 각각 불린다. 구조체 필드에는 기본값을 둘 수 있고 레코드 리터럴로 일부만 채운다(`fs.read(path, {limit=10})`이면 offset은 필드의 기본값). 둘 다 0.4.15 CLI에서 `use fs 'fs.cy'`로 확인했다(2026-11-20). 호스트 로더가 돌려준 모듈 소스와 세션 VM에서는 확인하지 않았다.
- 바인딩은 `Future[!T]`를 돌려주고 래퍼가 await한다. 승인이 필요 없으면 호스트 함수 안에서 바로 완료해 await가 VM을 빠져나오지 않는다. 물어야 할 때만 미완료 Future가 되고 eval이 CL_AWAIT로 돌아온다 (02 절차 4, ADR 0011, 0016).
- 스파이크가 완료해 본 것은 `Future[!str]`(fs.read, proc.exec)과 `Future[!void]`(fs.write, 값 없이 완료)다. cyber.h의 cl_future_complete는 값을 "호스트 함수가 돌려주는 모양"으로 복사한다고 하고 int, str, []T의 모양을 적는다. 구조체(`!ExecResult`, `!Stat`, `!HttpResult`)와 `![]str`을 Future로 완료하는 것은 확인하지 않았다.
- Future의 타입은 cl_find_type(vm, "Future[!str]")처럼 이름으로 찾는다. 호스트 선언이 그 타입을 이름 지은 뒤에만 찾히고 reset 뒤에는 무효다 (08).

정한 것 (ADR 0031. 능력 표는 사용자가 편집한다, ADR 0012)

- 생략할 수 있는 인자: 생략할 인자가 하나인 능력은 인자 수가 다른 래퍼 둘을 둔다(`fs.list()`와 `fs.list(path)`). 둘 이상인 능력(fs.read, fs.search, net.fetch)은 필수 인자만 받는 꼴과 마지막 인자로 옵션 구조체를 받는 꼴을 둔다(`fs.read(p)`와 `fs.read(p, {limit=50})`). 옵션 구조체의 필드 기본값이 04 표의 `= 값`이다. 래퍼는 능력마다 둘을 넘지 않는다. direct 모드의 JSON Schema에서 생략할 수 있는 인자와 옵션 구조체의 필드는 선택 속성이다.
  - 근거: 지금 빌드로 된다. 인자 수가 다른 래퍼는 모델이 다른 언어에서 익힌 꼴이고, 옵션 구조체는 이름으로 일부만 준다.
  - 버린 것: 생략 없이 모든 인자 받기(호출이 길다). cyber에 기본값 매개변수 요청(ADR 0010)은 평가의 실패 유형에 키워드 인자나 기본값 시도가 되풀이될 때 낸다.
  - runtime 단계에서 세션 VM의 호스트 모듈 소스로 오버로드와 옵션 구조체를 먼저 확인한다 (TODO M1).
- 구조체를 돌려주는 능력의 Future: runtime 단계의 첫 검사로 `Future[!ExecResult]` 같은 구조체 완료와 `Future[![]str]`을 확인한다 (TODO M1). 안 되면 cyber에 요청한다(ADR 0010, 0019). 결과를 str로 돌려주고 래퍼가 json으로 푸는 우회는 본체에 옮기지 않는다.
- ui.ask의 대기는 승인과 같은 CL_AWAIT 경로다. 능력이 미완료 Future를 돌려주고, 루프의 바닥에서 질문을 이벤트로 내고, 답으로 Future를 완료한 뒤 resume한다. 질문 요청은 승인 요청과 나란히 이벤트 타입에 있다 (12 이벤트 요구). 취소는 승인과 같이 resume하지 않고 버린다. 벽시계는 답을 기다리는 시간을 세지 않는다. 헤드리스는 사람에게 묻지 않고 오류 값으로 완료한다 (04). 근거는 ADR 0011과 같다.

## 사양 쓰는 법

사양은 문서가 아니라 모델이 읽는 계약이다. 영어, 짧은 문장으로 쓴다.

1. 한 문장 요약
2. 언제 쓰고 언제 쓰지 않는지. 이웃 능력과의 경계 (예: 내용 검색은 fs.search, proc.exec로 rg를 부르지 않는다)
3. 결과 모양과 상한
4. 전제와 부작용 (예: fs.edit는 같은 세션에서 fs.read가 선행해야 한다)
5. 호출 예 한두 줄

사양 전체가 요청마다 실리므로 토큰 예산을 둔다: Cyber 부분집합 안내 4,000 토큰, 능력 사양 3,000 토큰. 예산을 넘는 능력은 한 줄 요약만 싣고 help(name)로 전체 사양을 조회하게 한다.

## 이름과 모듈

- 이름은 모듈.동사 꼴이다. 모듈은 fs, proc, net, ui, memo.
- 세션 시작 때 호스트가 머리말 스크립트를 한 번 eval해 호스트 모듈의 use 선언을 넣는다. persist_main이 use를 이어 주므로 모델은 호스트 모듈의 use를 쓰지 않는다.
- 호스트 로더가 허용하는 모듈은 cyber 표준 모듈 core, meta, c, math, json, toon, regex, peg, time, path, test와 위의 호스트 모듈뿐이다(meta와 c는 다른 모듈의 의존). io, cy는 로드를 거부하고 os는 라이브러리에 없다 (05, ADR 0026, 0028). 순수 계산은 표준 모듈의 몫이고 능력으로 만들지 않는다 (ADR 0010).

## 검증

- 정적 타입이 1차 검증이다. 타입 오류는 validate 단계에서 컴파일 오류로 돌아간다.
- 값 검증(경로 범위, 크기, 패턴 문법)은 본체가 하고 오류 문구로 가르친다. 오류는 무엇이 틀렸는지와 다음에 할 일을 함께 말한다. 예: old text matches 3 places; add surrounding lines to make it unique, or pass replace_all = true.
- 모델이 보는 반환은 !T다(바인딩은 Future[!T]를 돌려주고 래퍼가 await한다, 위 절). 실패는 오류 값으로 돌아가 스크립트가 처리할 수 있다. 처리하지 않으면 panic이 되어 결과로 돌아간다.

## 본체 작성 규칙

- 본체는 Zig 값만 다룬다. Cyber 값 변환과 해제는 생성된 바인딩이 한다. 값으로 받은 str, []T는 바인딩이 본체 호출 뒤 cl_str_deinit, cl_slice_deinit으로 해제한다.
- 모든 실패 경로는 오류로 반환한다. @panic, unreachable, abort로 프로세스를 죽이지 않는다.
- 실행 직전에 권한 게이트를 부른다 (05). 게이트 호출도 바인딩 층에 있어 본체가 빠뜨릴 수 없다.
- 막힐 수 있는 본체는 자체 시간 제한을 갖고 취소 플래그를 100 ms 간격 이하로 확인한다. 스텝 벽시계는 능력 안의 시간을 세지 않으므로(02) 능력의 시간 제한이 그 호출의 유일한 상한이다.
- 경로는 작업 디렉터리 기준 상대 경로로 받고 돌려준다. 내부에서는 정규화한 절대 경로로 정책을 판정한다 (심볼릭 링크를 따라간 뒤).
- 부작용만 있는 능력도 완료 요약을 돌려준다. 빈 결과는 없다.
- 호출마다 감사 기록을 남긴다: 능력, 인자 요약, 결정, 걸린 시간, 결과 크기 (07).

## 결과 상한과 넘침

- 상한은 모델로 가는 쪽에 건다 (ADR 0021). 스크립트는 큰 값을 받아 안에서 줄일 수 있어야 한다. 이것이 CodeAct의 이점이다.
- 스크립트 결과(출력과 마지막 값) 상한: 기본 20,000자. 넘치면 자르기만 하지 않는다. 전체를 세션 디렉터리의 파일로 쓰고, 결과에는 앞 200줄과 뒤 50줄, 생략된 줄 수, 파일 경로를 담는다. 모델은 fs.read나 fs.search로 필요한 부분을 다시 본다.
- 능력이 스크립트에 돌려주는 값의 상한: 기본 1 MiB. 넘치면 앞뒤 512 KiB를 남기고 그 사이에 생략 표시 줄(생략한 바이트 수, 넘침 파일 경로)을 넣고, 전체를 넘침 파일로 쓴다. 메모리 상한(05) 아래에서 충분히 작은 값이다.
- 바이너리는 내용 대신 종류와 크기를 돌려준다.
- 사양에 지시한다: 큰 결과는 스크립트 안에서 줄여 필요한 것만 출력하라.

## 파일 상태 추적

- 세션은 읽은 파일의 경로, mtime, 크기를 기억한다.
- fs.edit와 기존 파일에 대한 fs.write는 읽은 적이 없거나 읽은 뒤 바뀐 파일을 거부하고 다시 읽으라고 알린다. 사용자가 편집기에서 고친 것을 덮어쓰지 않기 위해서다.
- 쓰기 전에 원본을 세션 디렉터리에 한 번 보관한다 (턴마다 파일당 처음 한 번). 되돌리기(/rewind)의 재료다 (06).

## 프로세스 실행

- 능력은 둘이다. proc.exec는 인자 배열을 받아 셸 없이 실행한다. proc.sh는 문자열을 /bin/sh -c로 실행한다 (04).
- 긴 작업은 proc.start가 작업 ID를 돌려주고 proc.output, proc.kill로 다룬다. 종료 대상은 하네스가 시작한 작업으로 한정한다.
- 시간 제한에 걸리면 지금까지의 출력과 timed out을 돌려준다. 프로세스 그룹째 종료한다.
- 환경: 작업 디렉터리 고정, stdin은 닫는다, TERM=dumb, 페이저와 색을 끈다. 제공자 항목의 key_env가 가리키는 키 변수(DEEPSEEK_API_KEY, OPENROUTER_API_KEY 등)는 자식 환경에서 지운다 (05).
- 세션이 끝나면 하네스가 시작한 프로세스를 모두 정리한다.

## 병렬

- v1은 스크립트의 spawn을 막는다 (연료(fuel)가 스레드마다 따로 세어지고, 승인 프롬프트가 겹친다).
- 병렬이 필요해지면 호스트가 제공한다: 읽기 등급 호출 여럿을 한 번에 받는 능력을 후속으로 둔다.

## 하네스가 지원하지 않는 것

- 대화형 TTY 프로그램: stdin을 닫아 비대화형으로 만든다. 입력을 기다리면 시간 제한으로 끝난다
- 외부 세션(DB 셸) 유지: 후속
- 사람 입력이 필요한 흐름(OAuth): 후속
