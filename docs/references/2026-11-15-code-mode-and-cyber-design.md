### 1.2 갈래

모두 "모델이 쓴 코드를 어디서, 어떤 경계 안에서 돌릴까"에 대한 답이다.

| 구현 | 실행 위치 | 격리 경계 | 성격 |
| --- | --- | --- | --- |
| node:vm (전언, Claude Code) | 같은 프로세스, 같은 런타임 | 사실상 없다. Node 문서는 vm을 보안 장치로 쓰지 말라고 적는다 | 가장 싸다. 안전은 넘겨 주는 도구 함수와 권한 경로가 맡는다 |
| V8 isolate (전언, Codex) | isolate | 힙 분리, 메모리 한도 | 무겁지만 JS가 완전하고 경계가 실제로 있다 |
| 자체 인터프리터 (전언, OpenCode) | 같은 프로세스 | 언어 표면을 직접 정한다 | 통제가 가장 크고 유지 비용이 든다 |
| QuickJS (pi) | 내장 인터프리터 | 별도 힙, 실행 한도 | 작고 넣기 쉽다 |
| libcyber (tars-agent) | 정적 링크, 세션 VM | 능력 표에 있는 것만 보인다. deny_raw_ptrs, deny_spawn, 메모리 상한, 벽시계 | 내장 런타임 갈래. 언어와 런타임을 우리가 고친다 (ADR 0010) |

### 1.3 Claude Code 공식 문서가 말하는 것

- 실험 기능이고 기본은 꺼져 있다. `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1`로 켠다.
- 모델은 JavaScript를 쓴다. 셸은 `` $`cmd` `` 도우미(`.text()`, `.nothrow()`), 편집은 `edit(file, old, new)`다.
- 코드 전체가 `REPL`이라는 도구 호출 하나다. `PreToolUse` hook은 `tool_input.code`로 코드를 읽는다.
- 코드 안의 도구 호출 하나하나가 평소 권한 경로(`deny`·`ask` 규칙, `PreToolUse` hook)를 지난다.
- auto mode의 분류기는 실행 전에 코드 전체를 한 번 본다. 문서 스스로 "실행 중에 계산된 값(검색 결과에서 얻은 경로 같은 것)은 보지 못한다"고 적는다.
- Bash 규칙은 명령 문자열로 맞추므로, 규칙이 맞추지 못하는 형태로 쓴 명령은 돌 수 있다고 경고한다.
- 시간 한도는 대기 모드 10분(권한 프롬프트에서 기다린 시간 포함), 백그라운드 2시간이다. 메모리와 출력 한도는 적혀 있지 않다.
- 호출 사이에 변수가 이어지는지는 적혀 있지 않다. Code Mode로 시작한 세션은 Code Mode를 켠 채로만 재개된다.
- 화면에는 호출 결과(편집 diff)를 보이고, 코드는 접힌 "Code" 줄로 둔다(`Ctrl+O`).

### 1.4 tars-agent와 맞대 보기

| 주제 | Claude Code | tars-agent | 근거 |
| --- | --- | --- | --- |
| 안전의 자리 | 호출 경로의 권한 규칙 | 능력 표(없는 능력은 주입되지 않음)와 호출마다의 게이트 | ADR 0006, 0007 |
| 승인 시점 | auto mode는 실행 전 코드 검토, 그 밖은 호출마다 | 호출마다, 실제 인자로. 승인 대기는 VM 밖 | ADR 0011 |
| 셸 규칙 | 문자열 매칭, 우회 가능성을 문서가 인정 | proc.exec(인자 배열)와 proc.sh를 나누고 셸 문자열 분류기는 만들지 않음. 실행된 프로세스는 Landlock | ADR 0007 |
| 시간 한도 | 권한 프롬프트 시간까지 셈 | 벽시계는 VM 안 시간만. 승인 대기와 능력 본체 시간은 뺌 | ADR 0021의 8 |
| 재개 | 같은 모드로만 | VM 상태는 복원하지 않음. 히스토리, memo, 할 일, 파일 상태만 | ADR 0008의 4 |
| 실패 값 | 예외, `.nothrow()` | `!T` 오류 값, `!else \|err\|` | ADR 0001 |

tars-agent에 없는 것: 실행 전에 스크립트 전체를 보는 검토. 능력 호출마다 실제 인자로 승인하므로 런타임 값을 놓치는 약점은 없다. 위험한 스크립트를 실행 전에 거절하는 단계를 둘지는 정하지 않았다.

### 1.5 내장 런타임의 값

비용

- 모델이 Cyber를 모른다. 시스템 프롬프트가 direct 331바이트, CodeAct 20,867바이트다(검토 문서 docs/spikes/2026-11-14-m0-spikes-review.md 5절).
- 작은 모델은 과제당 컴파일 오류를 1.7번 낸다. 대부분 Python 습관이다.

이득

- 정적 타입 검사가 실행 전에 돈다. 컴파일 오류는 부작용 전에 나고, JS에서는 같은 실수가 실행 중 예외가 된다.
- 처음부터 쥐고 있는 권한이 없다. 능력 표에 없는 것은 보이지 않는다.
- 오류가 값이라 오류 어휘가 곧 도구 설계다(2.2).
- 모델이 틀리는 곳을 cyber의 문구와 규칙으로 고칠 수 있다.

남은 판정은 eval(과제 20개, CodeAct 대 direct, ADR 0006)이 한다.

## 2. cyber PR #7을 CodeAct 관점에서

### 2.1 출처

soomtong/cyber PR #7 "Review Nimony design principles against Cyber", 문서 docs/study/11-design-principles-review.md. 2026-11-15 기준 열린 PR이다. 결정 문서가 아니고, cyber는 채택할 항목마다 결정을 따로 쓴다. 1절은 Nim 3.0(Nimony), 2절은 Nim 2 · Lean 4 · Koka의 마지막 사용 분석이다.

### 2.2 우리에게 닿는 정도

CodeAct에서 모델은 Cyber를 쓰는 사람이다. 비용은 컴파일 오류로 버리는 턴과 틀린 분기다.

| PR 항목 | CodeAct에 주는 효과 | 정도 |
| --- | --- | --- |
| 1.4 A 표준 오류 이름(errno · Windows · HTTP 매핑) | 모델이 오류 이름으로 분기한다. 같은 실패가 함수마다 다른 이름이거나 `Unknown`이면 분기가 틀린다. 능력 표의 오류 어휘를 같은 집합으로 맞출 수 있다. 스파이크의 능력은 이미 `error.NotFound`를 쓴다 | 높음 |
| 2.4 C 빌림의 비어휘적 수명 | 매뉴얼은 `elem := &a[2]; a << 4`가 된다고 하지만 거절된다. 모델은 매뉴얼대로 쓴다 | 중간 |
| 2.4 D · E 암시적 이동 | 마지막 사용이면 `move` 없이 이동한다. 작은 모델의 컴파일 오류 턴이 준다 | 중간, cyber 0.5 뒤 |
| 2.4 B `Slice` 값 의미 | 지금은 컴파일되고 결과가 틀린다. 모델이 틀린 결과로 다음 판단을 한다 | 중간, 빈도는 모른다 |
| 1.4 C 1단계 특수화 경로를 붙인 오류 문구 | `let x := 1`이 고치는 법을 말하는 오류 문구와 같은 줄기 | 중간 |
| 1.3.3 OOM은 panic, VM 재사용 | 세션 VM 구조와 맞는다 | 이미 맞음 |
| 1.4 D 구조적 병렬 루프 | 세션 VM은 deny_spawn이다 | 낮음 |
| 1.4 B 순환 가능 타입의 정적 판정 | 짧은 스크립트에서 `^T` 순환은 드물다 | 낮음 |

### 2.3 후속 후보

- 능력 표를 설계할 때 오류 어휘를 cyber의 표준 집합과 함께 정한다. 따로 정하면 두 번 고친다.
- PR 1.7의 결정 1(A를 0.4.12에 넣을지)에 tars-agent의 근거를 요청서로 보낸다.
- eval에서 `move`와 빌림 관련 컴파일 오류의 빈도를 센다. 2.4 C · D의 우선순위 근거가 된다.
